## 1. 项目是什么；本文件不是什么

Replicated Suite 是面向 ArcheRage RU 玩家、免费分发并长期维护的综合辅助插件。核心目标按优先级为：**正确性与稳定性、用户升级兼容、可维护性、性能、扩展性**。不能把功能数量或测试数量当成完成度。

用户长期使用的服务器版本背景为 RU 10.0；本会话的实机报告写明 `LUA=Lua 5.1`。新 Agent 必须重新确认当前客户端、接口和运行文件，不能将这些背景当作永久事实。

这是 **Lua 客户端 Addon，不是 Unreal Engine 工程**。用户另有 UE5/LGameplayFramework 项目，其中 Authority/Proxy、UObject、OnRep、GetLifetimeReplicatedProps、FastArray 的要求不能搬到这里。这里的 Authority 是业务数据所有者，不是网络服务器权限。不得为这个任务创建 P2P 协议或 UE 组件。

本文件中的最新行为约定优先于旧聊天摘要、过时文档和技能历史叙述；实际源码与现场证据决定实现。若出现冲突，记录双方依据再决定，不选择对自己最方便的一方。

## 4. 架构与生命周期

保持唯一入口，内部遵循 **Core + Services + Feature Modules + UI**。

- Core 提供通用机制；Service 提供共享事实；Feature 保留业务判断；UI 只消费投影并发出命令。
- 不因为两个功能在同一分类，就强制同时启动。死亡回顾不依赖 DPS 运行；战备、增益数量、首领警报也不为了复用方便启动高成本战斗统计。
- 高频功能必须有独立需求、订阅、缓存和清理。共享服务按消费者管理；释放自己不能停止别人的需求。
- 明确区分 `Feature Enabled`、`HUD Visible`、`Collapsed`、`Page Open`、`Calibration Active`。隐藏窗口不是停用；个人主动开启的后台提醒可能有自己的消费者。
- owner/generation、目标身份、请求身份是生命周期的一部分。晚到回调不能更新新目标；取消期间已进入执行的回调也必须再次检查有效性。
- 模块间通过已存在的服务/EventBus通信，不直接交叉访问别人的可写状态。不要复制第二套 Buff、目标、队列或窗口位置系统。
- 现有 `features/rs_business_bridge.lua` 和 `features/life/rs_life_m16_bundle.lua` 含实际业务，不能因名字像“旧桥”就删除。是否遗留由加载与调用决定。

生产文件按 `toc.g` 依赖顺序加载；测试/开发脚本不入 TOC。目录存在不等于文件活跃，亦不能为了“TOC对账全绿”把所有 Lua 都放进 TOC。

## 5. 最近多轮工作：必须保留的结果及仍未证明的范围

本节表示“已交付代码或已明确用户语义”，不是承诺用户本机都已覆盖，更不是 RU 全面验收。详细定位见证据文档。

### 5.1 状态追踪、类型识别与PVP

**冻结列表 = 持续观察并留存出现过的状态，不是按下按钮那一帧的快照。** 自身/目标、Buff/Debuff/Hidden 的覆盖分别记录。0.5秒等短状态被观测到后仍可在管理列表中找到；不能承诺未被API/采样捕获的状态也一定记录到。留存列表不能反过来喂给实时HUD，避免把已消失Buff画成生效中。

内置状态库需有图标，一次导入到用户追踪集合；不要求新用户逐个加载14个天赋。允许按已追踪/隐藏/待分类筛选、取消当前未出现的状态。用户取消的ID不能被后台“补齐新版”悄悄加回。滑翔翼、翅膀、坐骑/伙伴技能CD属于既有需求，实际接入及观察范围要读当前实现，不能依据“有技能库”就判定CD已完成。

**自己显示实际装备；敌人显示实际Buff证明的装备类型。** 用户提供过：716=皮甲，4899=双持，8226=盾牌，8227=双手武器；同类其他ID从项目目录查证。类型相同的换装不要求换类型图标；不能把自己武器冒充敌人武器。没有数据或出现矛盾时显示未知/撤回旧图，不猜物品名、品质或具体部位。

职业名称前已接入类别图标，职业图标可独立校准；不是每个三天赋组合都有独一无二的图案。自身与目标各自保存。新增组件必须一并接入默认、规范化、保存、校准、预览、实际显示、导出、恢复、清理和测试，不能只画出来。

PVP已调整为：两个可见单位的父容器按渲染帧跟随；内容按脏标记/事件更新；装备变化与Buff变化分类合并，保留首次待执行时间；自己装备约200ms兜底，慢元数据约1秒；普通事件常用50ms合并。**这些是当前代码策略，不是API实时性或端到端50ms保证。** 不把它推广成每帧全技能扫描，不用无限平滑/插值掩盖旧事实。

原生纹理/文字明确拒写时，不能推进“已显示”缓存；旧目标图标及时清理。持续事件洪流、切目标、取消后回调、原生拒写重试必须进入回归。现有 `pvp-hud-1` 是定位标记，不是性能合格证。

### 5.2 首领机制、倒计时与HUD

已交付逐条规则开关、批量保存、选中规则测试、来源隔离、六秒测试、HUD拖动/尺寸/位置保存，以及可选“未收录读条”。已知目录只是**三条读条和两条自身Debuff规则**，不等于完整黑龙技能库。

倒计时按同一时钟的绝对截止点走秒，提示显示时长不能截断真实读条；重复观测不能每次重新开始。任务存在性、单位、Native文字确认、同名下一次施法和不可读目标的段结束要分别判断。测试必须真的推进时间，不能只看到一个“6”就成功。

“未收录读条”只反映实际被观察的目标/关注目标读条；不能预测瞬发、全场所有首领或下一次冷却。单提示通道不等于多技能时间轴。低优先级个人提示不能抢占首领提示，清理一类来源不能清掉另一类。

用户曾报告黑龙倒计时卡住、测试不走秒、HUD不可调整；后续有代码修补及离线回归，但本交接不声明真实黑龙场景已全部修好。没有新实机证据时，不循环再发同类猜测补丁。

### 5.3 增益数量、随机商店、首页收入

增益容量当前是普通/隐藏两类原始计数、观察峰值和个人阈值提醒；未知不是0，两类不能直接相加冒充真实总容量，阈值不代表服务器上限或顶替顺序。启用有效个人提醒后可以独立后台观察；关闭功能才释放该模块需求。

随机商店当前是**读取计数**，不是刷新商店/购买。默认手动，可选可见页每秒读取；离页清理，最近变化最多12条。下降或断档另起观察段，不能推断每日额度、消费金额或剩余次数。

今日收支已有服务器日期账本，但金币/荣誉/经验/生活点真实来源未全部接通。任务文本或预计奖励不是到账；无合法来源必须显示未接入，不能填0做出完整报表。

### 5.4 存档、故障报告与复制

保留现有编码、envelope/canonical、回读确认和写保护。不因为 SaveData 返回成功就报保存成功；也不能靠去掉指纹字段、重置配置、跳过历史校验或随意加known-pair消除错误。

用户曾给出 `buffs.y` 保存前-2、回读后规范化0的差异。后续负数传输已保护，但没有当次原始LoadData就不能声称一定是底层“吃负数”或float精度造成。0、false、空串、空表、稀疏表、长ID序列和不同数值表示均需在真实链路分别验证。

保留“加载正常但后续耐久保存失败”的诊断，不仅收集加载写保护。恢复候选只能在严格边界内通过历史原指纹验证，未知mismatch继续保护。**普通重载保存失败时，仍保留用户用重载加载修复代码的出口，并警示未保存改动可能丢失。** 恢复探针不可在无授权时改游戏存档。

诊断只覆盖本次加载以来已记录错误；不能补回重载前、客户端内部或被淘汰的证据。用户复现后打印一次完整报告，用同一报告ID逐页复制。编辑框按实际容量回读后分页，显式上一页/下一页；翻页不重新自检、不重新读档。禁止3500字节短摘要丢根因、用“打印”隐式翻页或为满足预算静默删证据。

等待后Ctrl+C失败不能直接归因于定时SetText；先查重复几何、SetText次数、焦点所有权和原生事件。空闲期间不反复改正文和锚点，不能通过抢聊天焦点掩盖问题。

## 6. 经常出错的公共UI与业务边界

| 范围 | 不可回退约定 |
|---|---|
| 坐标 | 左上角原点、X向右、Y向下；界面“向上”通常减Y。但存储历史坐标与当前screen/world/popup lane必须看转换，不全局反号。 |
| 分辨率 | 覆盖1024×768、1280×768、1920×1080、2560×1440及实际UI缩放；不每个分辨率写魔法偏移。 |

| 输入 | 自动刷新不覆盖未提交草稿；数值框提供明确“应用”，不只依赖Enter；应用、保存、回读失败反馈保持可见。 |
| Slider | 编辑框越过当前范围时，按已有合法范围策略调整并保存，不被刷新强行拉回旧值。 |
| 拖动/缩放 | 沿已有Windowing/Native捕获做交互；禁止每页自行Tick鼠标差值生成第二坐标权威。 |

| DPS/战斗统计 | PVP/PVE、伤害/治疗/承伤分别累计；榜单显示限额不截断后台合法事实；保留自己与人工敌友纠错；不冒充全单位覆盖。 |
| 治疗/团队 | 可覆盖两团各50人，校准与团号/列表位置不能混淆；治疗计算与校准显示独立；职责分类沿现有目录和用户纠错。 |
| 换装 | 方案键与顺序稳定、重载不丢；战斗中只执行许可武器槽，防具/称号遵守现有约束；缺件按已定事务语义处理，不能无说明全停或换错实例。 |
| 整理背包 | 取/放快捷条、黑名单和仓储可见性沿现有Authority；满仓时允许的堆叠不能被“无空位”提前阻断；不可只为显示悬浮条放宽写门禁。 |

Quiet by Default不等于重置所有旧开关：保留已定义的默认启用模块及用户配置，不强制统一开关策略。

## 7. 不清楚的东西如何查证

### 7.1 先形成一个明确问题

不要写“API有问题”。写清：哪个能力、想知道哪个参数/返回字段/单位/权限/生命周期、它影响哪个可见行为，以及拿不到数据时应该怎样降级。

### 7.2 查证顺序

1. **真实调用链**：从页面按钮/事件进入，读调用方、封装、实际Native调用、投影与清理。记录参数顺序、owner-first回调、返回值包装和身份有效期。
2. **本地API和运行门禁**：读 `z_api_functions/api_functions.lua`、`ui_functions.lua`、相关delta和 `core/rs_api_capabilities.lua`。区分Allowed与Available/not allowed。存在函数名、能Import、pcall不抛错都不代表获准或业务成功。
3. **当前一手资料**：新增/变更能力需要联网核对有日期的RU官方公告和实际导出说明。社区、NA、AAClassic、AAEmu、旧插件只作线索；不能推翻当前禁用结论。记录查询日期、固定提交/页面、证据适用服务器。
4. **受控实机取证**：仅对允许且副作用明确的接口，使用低频、有界、可关闭、脱敏的读取探针。记录原始返回个数/中间nil、类型、值、单位、上下文、事件先后。不要枚举未知数字范围探活，不触碰not-allowed接口。
5. **独立故障模型**：保留真实被测层，Native边界使用明确模型；模拟空结果、延迟、拒写、断档、重入、单位切换。模型说明假设，不能反向证明客户端就是如此实现。
6. **仍不足就阻塞子任务**：写出已经查过什么、缺什么最小证据、临时降级、解锁条件；转到其他独立任务。不拿伪数据补齐按钮，不让一个研究项冻结整个目标模式。

未知字段不可从名字或值大小推断：毫秒/秒、total/remaining、金币单位、目标token、返回表中的index都需验证。保留合法0、false、空串与“不可用/失败/成功但为空”的区别。Lua中0、空串为真，不能笼统说是`or`吞掉了它们。

## 8. 当前必须保留的权限/证据阻塞

以下是本次历史代码门禁，不是永久API法令；只有新的一手开放证据、参数契约、授权及回归齐备，才能通过正规能力登记路径重新评估。

- `GetUnitsInSight`和已移除sight事件：不通过反射、改名或循环重试恢复。
- 钓鱼自动R和完整快捷键方案：没有合法完整action/源槽位集合、空绑定语义、回读与回滚证明，不读写未知绑定。
- 团队移动：没有合法队长/权限证明，不借不允许的`IsTeamOwner`放行；本人的SetRole不能当作修改别人职责接口。
- 强化逐槽位：没有合法equipSlotIndex集合和字段形态，不探测0..31等猜测范围；聚合只读与逐槽位阻塞分开。
- 传送配置：没有候选集合、稳定optionType、写入回读契约，不执行Option写入或未授权X2Warp动作。
- 攻城/招募/历史行情/真实收益：分别缺少场景与装备字段、请求参数身份、成交时间样本、合法实际变更来源；保留精确阻塞，不把“有页面”当成已完成。

## 9. 修改、验证、交付：一个闭环如何做

先写简短可验收的用户故事和数据契约 → 沿调用链定位 → 写能暴露当前缺口的反例 → 确认反例因正确原因失败 → 最小实现 → 正常/异常/停用/重载回归 → 检查差异和注释 → 在确定基线上应用**实际最终ZIP**复测 → 更新队列与检查点 → 继续下一项。

要求测试时钟真正推进、事件参数确实送到真实消费者、存档经历编码/读取/规范化、UI经过实际布局和Diff边界；不要用“返回都成功”的空Native替身消除恰好要测的故障。

缺真实Lua5.1时保留语法门禁blocked；5.3/5.4、LuaJIT、shim各自标注。Lua5.1语法也不证明沙箱标准库和Native行为。测试入口存在不代表全部依赖存在；跳过不能算通过，历史结果不能充本轮执行。

完成度分离：**代码实现、离线验证、RU验收、产品范围确认**。只有前两项的任务写“已实现待实机”，不自动移除导航“未完成”。用户明确确认某个范围已完成时，导航展示可以维持完成，同时仍记录范围外能力限制。

## 10. 自主执行、状态保存与停止条件

每轮只选一个有证据的业务闭环，允许将互相独立且不改同一底层的任务分给实际存在的子Agent；没有子Agent工具就顺序执行，不伪造独立评审。

在现有TODO中维护，不创建多个相互矛盾的“当前最终计划”。如果本地已有权威工作板，把本包种子合入并让本包只做链接。每个闭环更新 `04_RUN_STATE.md`，只记录可接续事实，不写长篇思维过程。

出现用户改动冲突、潜在数据丢失、未知权限写入、同一故障连续无新证据时，停止该动作并升级为明确阻塞。会话预算将尽时先保存源码、验证记录、未完成变更和下一条准确命令，再交付可验证部分；不要凭空承诺离线后继续运行。

最终统一五段：**完成内容、修改文件、性能影响、兼容风险、测试建议**，外加需要用户补充的最小证据及下一批顺序。所有“通过”对应实际命令、解释器、退出码、源文件版本；所有成品链接指向真实生成并核对的文件。
