# UI、输入与生命周期

## 从用户行为追踪

先确定目标是配置页、弹出菜单、HUD 还是世界投影。追踪点击 → 回调 → 配置/Commands → 共享事实 → 投影/刷新 → 当前可见实例。配置值已变但屏幕未变，应查订阅、失效通知和实例身份；不要立即新增第二份 UI 状态。

## 生命周期与共享需求

- 区分 Feature 启用、窗口可见、折叠和后台服务需求。隐藏不必停止仍被使用的统计；停用功能要释放其自身需求，共享服务是否继续由其他消费者决定。
- 注册、订阅、定时任务和回调应能追溯到 owner/generation。重载前停止旧运行时、释放旧任务与订阅；旧 generation 的迟到回调不能继续写新状态。
- 初始化应能重复执行而不累计监听器。连续重载后检查活动订阅数量、定时任务数量与每次点击实际执行次数，不能用节流掩盖重复注册。
- 使用项目已核对的销毁/隐藏路径。其他插件调用过某个销毁 API 不代表当前 RU 对象支持；也不能把某个项目缺少 reparent 能力说成所有版本都没有。

## 坐标和缩放

先为输入和输出分别标注坐标空间及已应用的变换，再决定在哪里转换一次。

| 来源/目标 | 检查重点 |
|---|---|
| 插件内部逻辑布局 | 框架缩放入口、父级缩放和锚点 |
| 外部 Native 控件、鼠标位置 | API 实际返回空间、当前分辨率与 DPI；是否已由框架转换 |
| 世界坐标投影到屏幕 | 投影返回空间与 HUD 消费约定，不能直接再乘插件缩放 |
| 菜单与触发控件 | 锚到实际触发实例的几何，别用无关窗口原点猜偏移 |

不要统一给所有坐标乘 `uiScale`。检查不同缩放、屏幕边缘、窗口移动、重开和保存位置恢复；存储的是逻辑坐标还是物理坐标也需与读取端一致。

## 点击与聊天焦点

先核对命中层级、透明覆盖、启用状态、处理器绑定和当前实例。禁止从 UE 的 Visibility 语义直接推导 RU 控件行为。

输入走项目现有路由；`OnKeyDown`、`OnKeyUp` 等名称不能凭其他框架经验当作可用事件。关闭窗口只处理本窗口树实际拥有的编辑焦点和处理器，不用全局 ClearFocus 干扰聊天。无焦点所有权证据时先加有限诊断。

验证点击一次生效、连续重载仍一次、显示/隐藏后状态一致、多档缩放位置正确，关闭插件窗口不抢聊天输入。涉及持久化时再读[存档与诊断](persistence-and-diagnostics.md)。

如果控件仍存在却显示了旧条目的结果，或订阅取消后重新出现，继续读[回调与请求契约](callback-and-request-contracts.md)，检查绑定代次、待加入队列及重复排期，不能只加 UI 节流。

## 有边框不等于子控件被布局

控件创建、父级可见、实际尺寸、命中区域和可交互状态逐层检查。装饰Border可能只负责绘边框，并不测量或安排子控件；原生编辑框也可能绕过框架的默认测量。出现“外框很大、内部1×1”时，优先核对Measure/Arrange、fill/auto/fixed、实际父子关系和本次激活是否早于首次布局，而不是反复抬zOrder。

使用当前RSUI有布局职责的容器或该组件的测量适配。只修已确认的局部错误，不能为了一个表单改变所有Border。回归保留真实布局算法，检查新建/改名按钮和输入框几何、多分辨率、缩放、首次显示、隐藏再激活；只assert对象非nil无法覆盖问题。

## 输入草稿与Diff Authority交接

这里的Authority是客户端组件/业务状态的所有权，不是UE网络Authority/Proxy。用户键入会先改变原生文字，框架缓存未必同时变化。若缓存仍为空，新建成功清空或取消恢复时可能把合法输入报成 `AUTHORITY_VIOLATION field=text`。

以实际输入协调器为边界：只在控件有效、已激活、owner/generation匹配时开启临时草稿；编辑中不让背景投影或刷新覆盖草稿。提交、取消、拒绝还原、失焦、隐藏、切页和退休时先同步合法草稿到Diff缓存，再关闭输入所有权。草稿同步不自动写Binding或Store。

错误owner、未编辑控件被外部改字、开始编辑前已有异常变化，仍需原strict检查。不能关闭所有text校验、全局ClearFocus或清零违规计数来“修复”。使用真实Diff、owner认领和按钮执行器回归中文键入、无需Enter直接点击、保存失败、取消再编辑和切页释放键盘。

原生返回是否成功、框架写入是否实际改变值、业务是否提交是不同层；例如底层“没变化”返回false不能未经契约转成业务失败。相反，业务明确拒绝也不能被 `and/or` 包装成nil成功，见[回调契约](callback-and-request-contracts.md)。

## 故障页必须早于写绑定构建

Store预检放在创建持久化开关/编辑Binding之前。只在OnActivate检查，可能已经被更早的控件构造读取失败拦截。

失败时使用只读保护页，显示阶段、Store和诊断入口；不创建会提交配置的控件，不启动该业务采集，不读大量明细，不默认覆盖旧档。真实控件错误仍交给PageHost报告，不能全吞异常。页面可打开与坏档已恢复分别验收。

## 工作台与小窗复用

提取可嵌入内容组件和纯读投影，不移动已存在的顶层悬浮窗到首页，也不因多个界面复制多套业务缓存。每个UI实例有自己的owner/输入/订阅，共享Feature数据和Commands。没有确认reparent能力就不设计依赖它的方案。

宽屏两列、窄屏明确命名切卡，先保信息层级与可读字号；空、关闭、未接入、陈旧、错误各有可解释状态。模糊的“下一行”不适合替代业务页签。切卡必须同时清理隐藏输入与自己的数据需求；首次激活早于测量也要回归。getter不能在render顺手读服务器时间、发拍卖请求或保存配置。

## 世界投影的额外检查

普通连线的有效屏幕点不一定依赖世界坐标成功；只有当前契约允许时才把两条读取分开。原生深度已明确否决的端点不能被任意回退重新画出来。裁剪、采样和Host锚点必须使用同源原生视口，不把插件逻辑尺寸再次作用到投影。

先裁剪可见线段再分配采样预算；仅在锚点写入真实成功后更新位置缓存，失败由既有刷新重试。目标缺失与投影算法错误分开记录，局部partial不能无条件显示正常。用户已确认完成的单位连线/范围辅助不因旧日志自动成为本轮改动范围。

## PVP运动与新增HUD组件的专门检查

位置更新不应触发整组内容重建。当前显示单位使用同源父容器跟随，图标只保留局部位置；原生拒写锚点不能推进位置缓存。屏幕裁剪与投影否决不可由平滑/回退“复活”。按实际显示需求停止任务，不以隐藏某个设置页误停战斗HUD。[PVP时效与渲染](pvp-hud-and-freshness.md)给出测量边界与压力用例。

新增图标除了能画，还应有独立校准、预览、应用/取消、保存/重载、模板导出与默认恢复入口。不能让组件只存在于渲染表，不在校准组件列表；详情见[HUD模板闭环](hud-template-and-defaults.md)。
