# HUD组件、模板导出与发行默认值

适用：新增职业图标但校准面板不能选；导出字符缺失；把已校准位置固化为新默认。必须先确认是在改个人配置、校准草稿还是发行默认，这三种请求不同。

## 新组件是一条链，不只是画一个Icon

组件ID/来源 → 配置字段及旧读 → 独立开关/尺寸/位置 → 校准组件列表 → 同源预览/实况 → 应用/取消/保存 → 模板导出 → 新默认/组件恢复/HUD恢复 → 重载与诊断。

将这条链变成组件验收清单。职业图标和职业文字应有明确的整体开关与局部坐标；调整图标不暗中挪文字。自己与目标的配置必须深度独立；同一初值不是同一可变表。`size=0`等旧语义按原契约保留，不因新增控件变成非法。

## 先验证副本，后讨论默认

接收 `RS-ERROR-PAGE-1` 先按[复制协议](diagnostic-report-workflow.md)核对全部字节、页码、偏移与校验。随后检查V2正文：META，加PLAYER/TARGET各BASE/AURA/EQUIP/CAST/CLASS，共11条。总长度通过仍需检查字段缺失、重复、未知格式、非有限数和来源。

聊天渲染能破坏符号；发送成功不证明复制成功。模板用现有安全报告框，不把正文送聊天、不借未经允许的剪贴板API。少行、坏页或PLAYER/TARGET标签损坏时停止应用；可指出已看见的数值，不推断丢失坐标。不同ID页面禁止拼接，完整相同重复页明确去重。

`source=draft`只证明导出当前草稿；数值框未应用的内容可能不在草稿。用户重载前需要保存并退出或明确接受丢弃。获取模板不能顺手保存、退出校准或重置默认。协议校验用于损坏检测，不能认证来源或允许执行其中Lua。

## 坐标不可偷换

记录viewport、uiScale、布局坐标版本与组件相对偏移。`x=0,y=0`可能是血条基准的局部微调，不是屏幕左上角。2560×1440导出不意味着其他分辨率要乘2560/宽度。确认渲染与导出使用同一坐标契约，Y向下为正；世界位置、原生像素、逻辑UI空间不要混算。

## 发行默认不参与重新解释旧指纹

先核对当前Store是否将默认补齐纳入canonical。若是：

1. 保留旧schema规范化与历史默认，验证旧数据的原指纹；不要直接改共享默认表造成旧值语义变化。
2. 已验证数据再按显式迁移分支补新字段，保留用户自己的false、0与局部布局；未知旧格式继续保护。
3. 新模板作为独立新建/显式恢复路径的覆盖层。新安装、恢复当前组件、恢复当前HUD、完整新默认快照指向同一模板来源。
4. 更新不能自动覆盖已有个人布局；恢复一个scope只改变该scope的布局，不清追踪列表或功能启停。
5. 使用旧schema样本对比前后canonical指纹及读取值；新版默认反向导出后按数字/字段比较，来源元信息差异明确处理，不为了字节一致伪造构建号。

当前项目保留历史目标装备模板，是兼容校验的线索，不是可直接删掉的“过时死代码”。先查引用再定清理范围；默认布局、物理codec与业务schema版本不能混为一谈。

## 收尾判断

有完整授权模板可以更新指定字段；没有模板不能凭截图猜数。导出功能曾为发行隐藏、用户后来要求恢复时采用最新明确需求，不被旧技能强制隐藏。验证负坐标、自己/目标独立、取消/失败、显式恢复、旧配置不变和新安装，无运行证据不能宣称所有分辨率实机通过。
