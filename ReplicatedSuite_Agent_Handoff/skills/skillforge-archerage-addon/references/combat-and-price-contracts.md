# 战斗统计与价格口径

用于 DPS/HPS 不一致、日志遗漏、重复累计、错误报价和历史利润变化。先确定要衡量什么，再判断社区代码是否符合该目标。

## 先写统计口径

逐击展示、个人有效输出、团队总伤害和整场 DPS 是不同产品。先确定时间窗口、开始/结束条件，以及持续伤害/治疗、宠物、自疗、过量治疗、吸收、免疫和脱战后的事件如何处理。

金额总和正确也不保证速率正确：持续时间取整场、个人活跃时间还是其他定义，分母为零时显示什么，都要明确。显示刷新频率与数据采集频率分开，隐藏窗口不应无意改变统计口径。

社区逐击日志可能有意排除 PERIODIC/DOT/HOT/TICK/REGEN 类别。这是展示选择，不能直接拿来计算完整 DPS/HPS；必须根据当前 RU 事件实际含义核对，不能仅凭事件名称猜测。

## 事件解析应可核验

按事件类别和客户端版本采集有限的原始样本：事件来源、实参数量、各位置的类型和值、当时的参与对象及预期行为。保留 nil 位置，不把有洞的参数表交给 `ipairs` 当完整参数序列。

将原始输入转换为当前项目所需的规范化记录，例如类别、来源/目标身份、技能、时间、数值、解析状态和证据出处；字段是内部表示，不代表宿主有同名 API。

- 不假设所有事件类别共享金额位置；不能从可选尾参找“第一个正数”就认定它是吸收量。
- 无法解析的金额保留未知及原因，不自动归零。不要统一取绝对值、去标点或舍入来掩盖格式/单位错误。
- 暴击、吸收、过量治疗等字段只采用已核对的契约。没有证据时可以先不纳入该细分指标，并标明覆盖限制。
- 显示姓名用于展示；稳定身份使用当前接口真正提供的证据。缺少稳定 ID 时记录身份范围和歧义，不能把同名或改名无声合并成确定事实。

## 重复事件与漏事件

先列出数据入口：原始事件、包装后的共享服务、文本日志或其他订阅，确认同一业务事实是否沿多条路径进入。优先消除重复接入，而不是在末端猜测去重。

存在可靠事件 ID/序列时按其契约判断重复。没有时，不用“同姓名 + 同金额 + 相近时间”无条件丢弃记录；这会误删合法连击或持续跳数。启发式处理须保留边界和可观测计数，不承诺精确去重。

让每个输入能解释落到哪里：已计入、按明确口径过滤、解析未知、证据确认的重复、等待补证。原始数量和各阶段计数可对账；伤害、治疗及过滤事件分别核对，不能靠扩大最终倍率补齐。

最小回放包含普通命中、持续跳数、自疗/宠物的目标口径、同额连续命中、重复入口、未知字段和晚到事件。以已知原始序列计算预期总量和分母，再比较解析—分类—累计—显示每个边界。尚无原始数据时只准备这些检查，不声称找到了用户丢失的具体事件。

## 价格与历史记录

价格记录同时需要物品身份、品质等适用属性、每件/每组单位、币种最小单位、数量及采集时间。当前接口未提供的字段标为未知；不要因为名称相同就默认同一个市场品类。

全局报价或搜索完成事件也会由用户自己的拍卖行操作触发。先按[请求关联契约](callback-and-request-contracts.md)确认归属，再更新对应缓存；未知身份的结果不能套给任意 pending 项。

区分三个概念：当前市场估价、交易发生时锁定的价格快照、真实到账证据。历史利润采用何种口径要由业务定义；当前报价刷新不能无条件改写已经确认的历史收益。缺少材料成本时显示“成本未知/估算”，不把未知成本当零而宣称净利润准确。

预计到账时间只是估计，不能自动冒充实际到账确认；时间到达后的状态名称须与证据相符。旧数据修复也要受影响范围和版本约束，不能把社区某个迁移函数直接套给其他项目。

回归：玩家手动搜索无关物品、旧窗口请求迟到、相同物品不同品质/数量单位、缓存过期、未知价格、历史快照锁定和未确认到账。价格变化的纯逻辑可模拟，实际接口和到账结果仍需游戏内核验。

这些检查由社区代码中的具体决策及其修复记录引出，不代表所有来源实现都已优于当前工程。采纳与舍弃依据见[来源](sources.md)。

## 有间隔不代表调用总量有界

一次“查15种材料”可能展开为每项多品质、名称搜索、控制物品协议探针及重试。即使每次间隔560ms，仍会形成很长的同步Native调用链。先列每层扇出和最坏调用数，测量单次Native、返回解析、成本计算、投影重建分别耗时。

普通询价采用用户明确触发的有限去重批次，只查必要品质；扩大品质/名称搜索作为单独的明确动作，不自动无穷回退。缓存区分当前报价、过期参考、未查询、无挂单和接口不可用，负结果短期冷却不能永久伪造无价。各数量、TTL和间隔由当前门禁与实测决定，本轮示例的4项/1000ms不作为RU全局限额。

重复点击不重复入队，批次完成停调度；首页、页面、悬浮窗共用报价状态和缓存。切换路线/模式、关闭Feature或取消时清排队请求并使旧请求代次无效；迟到结果不能改新路线或唤醒关闭界面。无法取消已进入的同步Native调用时如实说明，取消后仍检查结果归属。

一轮结果更新合并成本与列表失效通知，不每项完成就重算全部材料。打印诊断读取缓存而不是重新询价。不要用“加间隔/分帧”承诺消除一次Native调用内部的阻塞。

回归包含多界面连续点击、部分缓存命中、负缓存到期、普通/扩大模式、取消后旧结果、路线变化、关闭释放、超限和慢查询。当前估价与今天实际金币净变化是不同数据源，不能相互代替；收益按[服务器日期账本](server-day-ledger.md)接入。
