# 服务器日期账本与真实收益来源

适用于今日金币、荣誉、经验、生活点等统计；不是个人银行数据或交易所账户。先明确“收入”“支出”“净变化”与“预测利润”不是同一个量。

## 先有来源，再有数字

每个通道声明：已允许且实测的读取/事件、返回类型、最小单位、累计或增量、角色身份、时间来源和覆盖边界。方法存在、旧API表写着名称、官方声明开放、当前客户端确实返回可用数据，是不同证据。

本轮项目已经建立独立账本，但四种真实收益数据源尚未验证接通；UI应显示“待接入/未观测”，不显示伪造的0。账本测试通过只证明账本算法。后续有新官方证据时单独核对，不能把本轮未接入写成永久不可用，也不能顺带放开其他未验证接口。

不使用静态任务奖励、拍卖估价、预计售货款、聊天中随便匹配的正数或任务目标文本代替真实到账。解析聊天必须先有允许的来源、语言/类别/单位、去重和覆盖契约；没有这些时不采纳。完整价格口径见[战斗与价格](combat-and-price-contracts.md)。

## 余额差分的最小定义

```text
首次观察余额1000金：只记baseline，今日净变化0
下一次1010金：本次+10，累计+10
下一次1000金：本次-10，累计0
下一次995金：本次-5，累计-5
```

币种内部用已验证的最小整数单位，显示时换算。分别保留收入、支出和净额；连续同值观察不加账。首次baseline、下一观察与已提交累计要带通道/角色/日期身份。事件来源与余额来源同时接入须避免把同一变动算两次。

使用余额净变化时，转账、交易或花费只按实际余额反映，不能擅自归类成“盈利”。取不到期间明细时，声明这是所观察余额净变化，而不是完整收入分类。

经验可能升级归零、切到继承者阶段或跨等级阈值；没有已验证的累计量/增量契约不能直接相减，也不能无条件忽略所有负值。各种点数仍需单独确认是否可扣除、封顶或重置。

## 日期与重载

按当前角色scope和**服务器自然日**独立持久化。日界限以产品明确的服务器日期定义为准，不自动把周期活动刷新时刻当午夜。日期API不可用、返回错误类型或回退时不切到电脑时区清账；保持最后有效日期并标记不可核验。

同日插件重载保留已经累计的值，在恢复观测时重新建立baseline，不能把整个背包余额再次记作收入。未观测间隔后的差值要有明确政策：没有归属证据不补记，标“有间断”。离线跨日后先滚到服务器新日再建baseline，不能把离线几天的差额全部计入今天。

只重置账本自己的今日累计与基线，不清换装、追踪、任务或其他Store。暂停统计保留已保存合计和对应日期；不能把昨天值贴成今天，恢复也不重复计数。

## 独立服务与纯读投影

隐藏首页不停止已启用记账；明确关闭统计才释放该服务的时钟任务/数据订阅。首页、悬浮窗读取同一账本投影，getter不读Native、不触发日期轮转或保存。日期检查和合法观察通过现有scheduler/事件入口触发，不在UI刷新中隐式执行。

可以合并保存，但需说明脏数据窗口与失败处理；日期、累计与baseline应原子提交。严格检查失败时不能为消错覆盖已保存当天数据。真实时间读取失败不等于金额0，错误字符串不得当日期显示。

## 验证范围

覆盖首次基线、+10/-10、相同读数、支出、同日重载、暂停/恢复、角色切换、午夜前后在线、离线跨日、时钟失败/回退、未知来源、经验升级、保存拒绝及旧格式读取。

分别报告纯账本测试、Native适配测试、客户端真实交易/收益观察；只在取得真实来源后验收“今日收益已可用”。界面再精美也不能替代这一数据边界。
