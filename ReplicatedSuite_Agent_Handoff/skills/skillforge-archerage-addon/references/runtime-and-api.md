# 运行时、加载与 API

## 先确定宿主

ArcheRage RU、ArcheRage NA、AAClassic、AAEmu 服务端及客户端内部源码属于不同证据范围。接口名相同也不能证明行为一致。向未知目标移植插件时，先确定宿主，再选择加载器、接口和测试方法。

RU 项目通常依赖 Lua 5.1 兼容写法，但必须核对当前工程环境。不要默认桌面 Lua 的文件系统、模块搜索路径或新版本语法在游戏沙箱存在。语法检查应标明解释器版本；其他版本加 shim 的模拟只验证所模拟的逻辑。

## 加载链

从实际入口和 `toc.g` 等清单追踪执行顺序：依赖何时注册、全局表何时建立、初始化何时调用。比较客户端实际加载目录与当前编辑目录，排除改到了未加载副本。

- 区分“文件在磁盘上”“文件已加载”“初始化完成”“事件实际到达”。记录首次失败的位置和已加载版本。
- 顶层注册只能依赖此时已存在的对象；运行时对象和用户配置可能要等生命周期入口才能读取。
- 模块是否使用 `require` 取决于项目加载约定，不能把其他项目的模块系统直接引进来。
- 清单只列生产加载依赖。工具、测试、文档不必加入；核对顺序比把所有 Lua 文件列进去更重要。

## 能力证据分层

| 证据 | 能说明什么 | 仍不能证明什么 |
|---|---|---|
| 社区用例、旧 API 导出表 | 某时某环境存在一种用法 | 当前 RU 允许调用 |
| 有日期的 RU 官方公告 | 某次更新声明开放、限制或移除 | 本机已更新、返回符合本任务 |
| 当前客户端中对象/方法存在 | 导出可见 | 允许执行、成功且覆盖所有对象 |
| 有限的运行观测 | 指定输入和环境下的行为 | 全地图、所有单位及所有状态都完整 |

先检查当前工程的 capability 状态和官方变更。已禁用或移除的能力不要通过高频重试、改名或绕过边界调用来“探活”；待有重新开放证据，再在允许范围内验证。可用但契约不明确的读取可做有界、低频、可停止的验证；带副作用操作使用明确的用户操作和既有业务路径。

已核对的时间例子：2026-06-10 公告加入 `GetUnitsInSight` 并移除 sight 事件，2026-08-19 公告又禁用该函数。旧插件调用成功不能推翻后续禁用；详见[来源](sources.md)。本资料是日期快照，不能代替未来更新检查。

## 调用与数据契约

- 分清对象方法与全局函数；冒号隐含的 `self` 不能套给全局函数。保留实参数量及中间 `nil`，别用不可靠的表长度截断可变参数。
- `pcall` 成功只说明没有抛 Lua 错误；继续检查 API 的逻辑返回、错误字段和结果结构。封装后的返回顺序也须读代码，不能凭习惯拆包。
- 区分未知、不可用、错误、成功但为空，以及合法的 `0`、`false`、空串。Lua 中 `0` 和空串为真；不能把零值损坏笼统归咎于 `or`。
- 单位 token 的含义、事件参数和有效期从当前契约或受控观测核对。不要把一个事件采到的实体集合叫做全部单位。
- 优先复用现有事件、缓存和按需调度；确需轮询时说明频率、预算、停止条件和数据时效，避免每帧全量扫描。

无法获得完整数据时，界面和业务明确降级：显示未知或覆盖范围，避免把“未观测到”当作“没有”。验证正常、空结果、不可用、限制状态和重载后的路径。

共享事件归属、异步请求确认和执行中取消见[回调与请求契约](callback-and-request-contracts.md)；战斗数值与价格字段接入见[战斗与价格口径](combat-and-price-contracts.md)。

## 插件重载与按需API核查

用户通过现有“重新加载文件”验证补丁时，先检查它是否确实停止旧runtime、重新加载TOC并建立新generation。它不是物理进程重启：Native内部缓存、服务器状态、磁盘写入和游戏事件历史不一定归零。不要要求每个代码补丁都退出游戏，也不要承诺重载会回滚一次失败的物理保存。保留某个Store保存失败后仍能进入修复/诊断的逃生路径。

本轮曾把API表中列于 `Available/not allowed functions` 的剪贴板方法当成可用；可见导出不是允许调用。先核对分类、项目门禁与有日期官方变化。若补丁引入新权限依据，只更新该项，不顺带放开余额/经验等其他接口。未来任务需要当前API状态时重新验证，不把本技能的2026-09材料当永久表。

新增任务目标读取还需要索引身份验证：明确查看详情时有界查询，读前/读后核对当前索引仍对应同一任务ID；发生重排就丢弃，不用旧数组位置刷新另一条任务。目标文本的存在不意味着完成计数或实际奖励到账，文字里的数字不能直接加入收益。

即使官方刚开放，也先记录返回类型和范围，再确定解析；不凭API名称发明字段、参数单位或可枚举范围。无合法来源就显示未接入，不能以静态估值填零冒充完成。每日统计的具体契约见[服务器日期账本](server-day-ledger.md)。

## Lua5.1验证门禁（2026-09-13补充）

先读取实机`_VERSION`，另记录本地解释器完整版本、平台、shim和Native替换范围。针对本项目Lua5.1基线，语法门禁必须用实际Lua5.1编译；缺少时明确blocked，继续允许源码分析和其他层验证，不把5.4的语法通过兑换为5.1通过。

重点核查：新版语法如`goto`/位运算/`//`/`<const>`，以及运行库差异`table.unpack`、`utf8`、`load`参数、`xpcall`传参、环境表。语法检查只抓语法，不会证明API可调用；保留中间nil和实参数量。`loadfile`加载返回函数不等于执行函数，离线语法工具不应执行整个插件。

Lua5.1默认数值类型是double且可定制，不能仅凭`_VERSION`推断客户端或SaveData存储精度。`-2→0`也不能自动归因于浮点精度。桌面文件系统、os库、C模块等存在不代表RU沙箱允许。依据：[Lua5.1参考手册](https://www.lua.org/manual/5.1/manual.html)；工具见[验证工具](verification-tools.md)。
