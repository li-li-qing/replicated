# 首领机制：倒计时、观察范围与可编辑HUD

“窗口出现”只证明一次呈现，不证明计时任务运行、期限递减或所有技能已收录。先读真实 `服务→调度→Presenter→Native`，不要因测试按钮有文字就通过验收。

## 两个截止时间

一个是提示何时隐藏，另一个是实际观察到的读条何时结束。单位统一、使用项目单调时钟，按 `max(0, deadline-now)` 求剩余，不用每次回调固定减0.1来计时。长帧后的秒数应跳到真实剩余，不追赶无界历史tick。

测试必须驱动真实调度和假时钟，验证六秒→五秒→…→隐藏及长帧，不允许测试自己直接改label代替计时链。六秒是这轮测试场景，不是所有技能时长。

同一段读条的反复采样不能不断重置截止时间；只有可靠的进度/段标识证明新段才重启。同名连续施法与同一读条的重复通知要区分。技能ID、实体、观察代次、进度重置证据按当前接口使用；仅“同名+时间接近”可作有限通知合并，不能证明同一施法实体。

任务布尔标记不等于任务真实注册/启用。修复丢失任务时保留原期限，已过期就隐藏；不得绕过调度器明确的熔断/停用，不增加常驻看门狗把每个停用任务复活。旧generation tick不能隐藏新提示。

## 显示提交与优先级

只在显示文字改变时写原生label；写失败不推进已显示缓存，有界重试并记录，持续失败撤下虚假的静止倒计时。按owner撤回当前提示，关闭首领模块不能清掉其他来源，普通提醒不能抢走高优先级首领提示。所有权与优先级都是项目契约，不能用全局Hide粗暴处理。

## 覆盖范围要诚实

规则目录、当前目标/关注目标实际读条、自身Debuff、预测CD是四种不同数据。三条读条规则+两条Debuff不叫“完整黑龙技能库”。开启“未收录读条”也只是显示实际暴露的读条，不会知道瞬发、未观察单位、未读到的技能或下一次CD。

未收录开关是否仅首领、是否包含普通怪、允许哪些观察token，要从当前产品语义核对并在UI说明；别因页面叫首领就假设所有输入已经判定为Boss。技能名匹配还需检查语言、ID与版本，禁止用聊天文字猜时间或编造技能ID。

## 可编辑闭环

HUD新增字段必须贯穿默认/规范化、Store/Commands、编辑草稿、预览/实况、保存/取消、重载和诊断。校准模式可拖动、完成后鼠标穿透；从源组件所有权释放焦点与拖动处理器，不能全局抢键盘。调整位置不重启倒计时；保存拒绝应回到原已提交位置并保留明确错误。

清理测试/校准提示不能误清真实战斗提示。设置页离开时结束编辑，但功能是否继续取决于Feature需求，不根据窗口隐藏猜测。分辨率切换、屏幕边缘、位置恢复均走同一坐标契约。

## 必测

测试按钮真实走秒；长于大字显示时长的读条；同名下一次施法；其他无关目标读取失败不锁住当前施法；多个观察源同时命中；原生文字拒写；任务丢失与熔断分别处理；拖动/应用失败/重载；离开设置页恢复穿透；停用一个来源不误清其他来源。

读条缺失与计时冻结可同时发生但不必同因。源码修正、离线时钟通过、黑龙实机反馈分别记录。来源见[本轮证据](maintenance-evidence-2026-09-13.json)。
