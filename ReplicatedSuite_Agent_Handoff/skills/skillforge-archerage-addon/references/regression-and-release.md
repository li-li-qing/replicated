# 回归证据、基线与增量交付

本页回答为什么“大量测试通过”仍可能反复失败，以及怎样交付最小、可验证的改动。不是要求每次改一个标题都搭建全量审计。

## 保留真正失效的那一层

| 故障 | 测试必须走过 | 会掩盖问题的替身 |
|---|---|---|
| 用户输入被报越权 | 真实Diff缓存、owner认领、编辑草稿与清理 | SetText只直接给字段赋值 |
| 图标完成不刷新 | 真实EventBus发布与订阅包装、当前页实例 | mock只传reason，漏掉owner |
| 输入框/按钮1×1 | 真实Measure/Arrange及Native子几何 | 只断言控件对象已创建 |
| 一键导入回读丢项 | 实际Catalog/Store/transport/耐久校验 | Native永远无限制深复制 |
| 保护页也打不开 | 真实PageHost、绑定构建顺序、失败Store | 只单测EnsureStoreLoaded |
| 旧数值不匹配 | 真实原档或明确模型、相同codec/canonical | 只造容易恢复的浮点，漏平台差异 |
| 报告复制不全 | 实际协议、UTF-8/转义、容量与回读 | 重复字符串容易压缩、无限容量编辑框 |
| 重载后双执行 | 真实注册/取消和generation检查 | 每例重建空mock却没测旧闭包 |

不可用Native使用可控替身，但公布哪些边界被替换。替身应能模拟nil/false/多返回、API失败、缺键、浮点格式、字符串改写、池化和迟到回调；不能把测试模型写成游戏事实。UI方法不返回值、返回false拒绝与状态数据false按该层契约区别对待。

## 单个修改的最小证据闭环

先写原故障与成功标准，运行当前实现的失败用例；修复后同例通过并保持相邻正常路径。解释每个断言抓住哪项行为，禁止为了绿灯删除失败断言或降低完整性检查。

覆盖顺序通常是入口/命令 → 关键实际框架 → 数据/Native边界 → 可见结果 → 关闭与重载。数据写入必须延伸至回读和下一次读取；输入必须覆盖取消、拒绝还原、失焦、切页、隐藏和退休。

对尚无原始输入的现场，诚实区分“能解释现象的模型”与“用户这份数据的复现”。修复一个样本后不要默认所有Store同因；自检为READY不替代旧配置、历史条目、明细页和保存回归。跳过的序列单列，不并入通过数。

## 多轮仍失败时停止哪件事

停止的是**继续发没有新证据的同类补丁**，不是停止调查。列出原失败是否相同、最新补丁内容是否加载、下一项能区分竞争假设的观测。检查取证工具是否在删证据、检查测试是否绕开真实失效层。

当前问题已提供完整证据时直接定位，不再次索取同一份UDF或重复Hash。证据缺失时使用现有固定分页或最小只读样本。一个阶段的成功应写成“页面已可打开/取证已送达/验证器已纠正”，不合并成“存档已恢复”。

## 选择与任务相称的验证

标题替换：读真实创建和更新路径，改文案与必要维护注释，检查语法/创建/可能溢出；不迁移存档、不重构框架。

组件改动：补真实布局、输入、生命周期与相邻使用方回归。共享Core改动：扩到依赖的Store和正常/故障边界。新功能：验证最短可观察路径与关闭释放，再确认持久化和共享需求。用户已确认完成的无关功能不因诊断旧计数被擅自再改。

没有客户端可以继续源码核对、模拟、夹具和交付，但要写明解释器及宿主差异。Lua5.4+兼容垫片、Linux数值格式、模拟Native不是Lua5.1/Windows/RU验收。保持测试不“只为契合实现而造数据”。

## 基线和补丁

确认用户原包、后续补丁顺序、实际修改内容、当前加载标识。全局版本标签可能长期不变，必要时使用文件摘要/局部补丁标记；不凭标签推断补丁没装。

只打实际新增/修改文件并保留项目相对路径；删除另外列出。当前项目的API参考目录只有变更时才进增量，没改则明确说明；开发工具/测试/文档不自动进运行时TOC。交付物排除UDF、玩家数据、Git元数据、临时缓存和与本次无关文件。

新目录重解压基线、按已确定顺序覆盖增量，再覆盖**最终ZIP本身**；核对内容摘要、唯一TOC依赖存在且顺序正确，并运行适用检查。未修改文件应保持字节一致，不能用“工作区通过”替代“交付包通过”。

升级物理格式时必须说明旧代码能否读、旧读是否保留、是否自动重写以及回退所需配套备份。只改文案则说明未动配置，不套用无关迁移警告。每个实际修改点留原因、owner/数据流、兼容边界、实现理由与维护风险注释；不要求在无关行灌满重复注释。

## 最终报告

Replicated Suite按项目约定统一报告：完成内容、修改文件（新增/修改/删除）、性能影响（CPU/内存/高频逻辑）、兼容风险、测试建议。小改可以简短，数值必须来自实际执行；正文准确区分源码核对、模拟/语法、客户端反馈、未运行部分。

补丁使用插件内重载验收；重载会重建插件generation但不是物理进程重启。保存失败仍应保留进入修复/诊断的路径，不能让重载按钮因一个坏Store完全不可用；同时提醒失败写入可能残留磁盘风险，不能假称自动回滚。

## 2026-09-13：少报一个通过，胜过多报一个错误保证

每次验证记录命令、工作目录、实际解释器/平台、输入摘要、退出码、通过/失败/跳过/阻断、替身范围、日志产物和执行日期。解释器和来源摘要只能证明所指内容一致，不证明语义覆盖。用例数量须来自当前执行器，断言数、测试方法数、脚本数不能混加；历史说明中的858项不抄为本轮结果。

优先新增能失败的反例：持续事件不饿死装备、位置帧不做元数据扫描、目标A→B→A、文字/纹理明确false拒绝、长帧倒计时、保持选区等待、旧默认canonical不变、所有新增组件导出和恢复齐全。测试应保留真正失败的层，而不增加方便替身的数量。

本技能自带的工具验证的是技能结构、接收协议与包内容；独立Agent无技能/有技能A/B是另一项实验，不具备子Agent能力时明确未执行，不能自问自答后填写正确率。GUI、游戏、剪贴板实测仍单列。用例见[评测办法](../evals/README.md)。

基线多轮合并时，全局BUILD相同不是补丁未安装的证明。维护可追溯的包顺序和文件摘要，不额外恢复缺失旧文件。增量ZIP核对与干净目录执行分两步；[audit_patch工具](verification-tools.md)只验证前者。小改不需要把整份工程作为交付物，也不必新建重复审计文档，但不得省略实际交付文件验证。

新增低频计数功能也需明确所有权和观察周期：原始计数不是消费金额/每日额度，读数下降或断档不跨段累计；自动读取默认、页面可见需求和Feature开关分别说明。只有离线和静态路径完成时保持待实机状态，不靠添加测试数把“未完成”改成“完成”。
