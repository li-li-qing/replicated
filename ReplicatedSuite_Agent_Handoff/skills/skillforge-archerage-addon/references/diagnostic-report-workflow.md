# 诊断：完整字符串、固定报告和明确分页

用于日志反馈、`RS-ERROR-PAGE-1`、`TEXT_LIMIT`、`TEXT_READBACK`、短摘要缺原档。以下是本轮用户明确后的 Replicated Suite 工作流；移植其他插件时先确认产品交互，而不是强制所有宿主采用同协议。

## 操作契约

```text
插件内重载 → 复现问题 → 运行自检/打印自检报告
           → 当前页全选复制 → 下一页 → 逐页反馈
```

上方“运行自检”“打印自检报告”，下方独立“上一页／页码／下一页”。打印时只生成一次报告正文和身份，内存保存完整快照；一个编辑框可复用显示N个逻辑页。翻页不重新自检、不读取存档、不改变ID、不暗中重划已交付页边界；边界按钮禁用而非悄悄绕回。再次打印才建立新快照并回第一页。

运行自检不清除本次加载的错误历史。离开页面、重新打印或重载何时释放当前报告必须明确告知；旧generation回调不能污染新报告。插件重载是常规代码生效与回归入口，不等于新游戏进程，不要求每个补丁都退出游戏。只有实际涉及物理文件一致性采集等条件，才说明为何需要关闭进程。

## 错误收集与内容结构

复用项目统一日志入口，保存有限的字符串片段、级别、来源、首次/末次时间、重复次数和generation；点击打印再拼接。不要每次事件把全文复制成更长字符串，也不要让日志收集器自己的异常递归刷日志。

推荐正文顺序：报告身份/版本与覆盖声明 → 失败检查 → 已记录错误 → 当前加载/回读/保存失败 → 相关服务和UI快照 → 必需的只读取证 → 覆盖与校验尾标。一个provider失败应有具体原因，仍继续收集其他部分。

区分本次加载已记录的错误、历史已淘汰记录、其他插件、客户端内部不可见错误。资源上限分为错误种类、每条长度、总报告、每次原档数量和每份原档预算；数值取自当前实现，不能承诺无限收集。“重复次数”“截断数”“省略数”“读取失败”不能省掉。

**编辑框容量不是删根因证据的理由。** 总报告安全预算内的正文应完整分页；只有总预算或采集失败才标记partial及缺失部分。旧 `RS-FOCUS-1` 仍可解析，但已经不是本项目当前默认；`raw=0/2` 即使首尾齐全，也代表两个原档都没送到。

## 编辑框容量与写入验证

1. 先确认父级布局和编辑框有效几何，完成显示与焦点激活。声明创建成功不代表控件真正可见。
2. 使用受限文本探测或实际第一页验证 `SetText/GetText` 往返；读取返回类型也须检查。声明MaxTextLength、字符串字符数与真实可接收字节数不是同一承诺。
3. 按UTF-8边界和**外层转义后的字节长度**分页，预留页头/尾标空间。报告内的反斜杠、换行、分号和尾标字符串都必须可逆。
4. 首次交付前可有限次降低页容量；已交付第一段后不得改变总页数和偏移。后续失败保留当前页重试，不把残缺文本交付成成功。
5. 先完成写入和回读校验，后发一条真实聊天回执。回执不是完整正文；不调用未获允许的剪贴板接口，不宣称“已复制”但实际只是显示。

本轮观察过声明9215、复制包38011、实际可用更小等情况；这些是当时实例，不是固定RU上限。压缩对可压缩测试串有效不意味着所有报告可一框显示。测试要含中文、随机/低重复文本、控制字符转义、极短容量以及激活焦点改变文本的替身。

## 接收端验证

以当前协议实现为准；以下字段是本轮 `RS-ERROR-PAGE-1` 的定位线索：`ID/PAGE/TOTAL_BYTES/TOTAL_CHECK/RAW_BYTES/RAW_CHECK/OFFSET/DATA_BYTES/DATA_CHECK`。

按声明的字节数取正文，不能简单按 `;RS-ERROR-PAGE-END` split：正文可能合法包含同样字样。检查同ID/同总数/同校验、页码齐全、偏移连续无重叠、逐页长度及校验，重组后再核对总包与解转义后的原文长度/校验。不可执行其中的Lua，不把Hash当密码学认证。

重复粘贴的完全相同页可明确去重；同页码内容冲突必须拒绝。不同ID不可混拼。仅收到1/N时可以分析已见错误，但必须说剩余覆盖未知，不虚构“整份验证通过”。先确认工具/解码器真实存在和参数再运行，不仅凭本页文件名假装执行。

## 诊断结论不能互相替代

| 输出 | 能得出的结论 | 不能得出的结论 |
|---|---|---|
| 全页和校验通过 | 传输副本一致 | 生成器没有省略、原档真实完整 |
| raw=0、copy_budget | 未附原文 | 用户没全选、错误不存在 |
| READY、B0/W0 | 本次已执行检查未报该类阻断 | 所有功能/数据正确、80个skipped序列已通过 |
| 加载failed=0 | 当前加载清单无失败 | 最近durable写入成功、磁盘回滚成功 |
| actions busy=1 | 采样时有动作 | 一定死锁；打印本身可能是当前动作 |
| 局部partial/degraded | 部分功能覆盖不足 | 整体READY能把它抹掉、一定是坐标算法错误 |

同一摘要重复多轮且无法区分假设时，不再要求用户发送它。先改证据采集边界，或经授权取得最小相关原档。必须分别说明诊断交付修复、业务恢复和用户旧数据恢复的完成情况。见[回归与发布](regression-and-release.md)。

## 等待后复制失效：静止窗口也要回归

用户`Ctrl+A→等2秒→Ctrl+C`失败，而快速复制成功，只证明时间相关干扰；不能未读代码就断言“两秒定时SetText”。分别记录正文实际写次数、逻辑布局请求与原生锚点/尺寸提交次数、焦点owner/代次、激活/失焦/隐藏和页切换。

同一快照页在空闲时不重写相同正文，不因原生尺寸回读抖动重放相同逻辑几何。真实布局变化与此前失败写入仍必须处理，不能永久缓存第一次尺寸。失焦事件先核对当前输入所有权和焦点状态；确有异步失焦通知问题才做有界下一帧复核，不永远夺回焦点，不注册多个focus轮询。

实际复制回归包含等待2/5/10秒、点聊天再返回、翻页后等待、窗口缩放、关闭/重开与重载；模拟只证明被建模的干扰路径，不能证明真实剪贴板内容。普通数字表单和只读报告选择区的焦点政策不同，不能为复制关闭整个框架的输入所有权检查。

聊天只发短回执；带分隔符的HUD模板也走报告框，发送API成功不是文本完整性证据。接收端现有脚本与随包工具分别验证；协议一致性与模板语义检查分开。见[模板导出](hud-template-and-defaults.md)。
