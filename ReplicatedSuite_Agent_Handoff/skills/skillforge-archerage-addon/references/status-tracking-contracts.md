# 状态追踪、短状态留存与内置目录

适用于内置Buff/Debuff库、当前状态、留存记录、追踪HUD及图标显示。这里的“冻结”采用用户后续明确的**持续留存已观察记录**语义，取代旧计划中的点击时快照；不要按“冻结”一词自行还原旧设计。

## 三种数据不互相覆盖

| 模型 | 权威数据 | 到期与保存 |
|---|---|---|
| 当前状态/正式HUD | 当前Native观察事实 | 时间继续变化，到期/消失后移除 |
| 留存记录 | 本次开启后实际观察到的历史 | 从未追踪也可收录，消失后仍留；会话有界，不写过期快照进Store |
| 已追踪 | 用户已提交的追踪集合+元数据 | 当前身上没有也能管理，取消后按Store持久化 |

打开留存后继续接收后来的状态，不只存点击时一帧。实际观察到0.2秒状态可以保留，但接口未暴露、开启前消失、采样间隙从未取得的状态不能凭空还原。事件即时观察与周期补采应使用已验证事件，不靠编造事件名实现。

“清空记录”不等于“停止留存”；是否继续记录由明确动作决定。关闭一个窗口只释放它自己的需求，禁用功能/重载按当前生命周期清理；留存和HUD独立消费者不互相误停。去重键需明确来源角色、效果ID以及是否区分目标身份，不能把变更目标的记录伪装成同一实体；每来源/目标上限、溢出和丢弃策略可见。

## 内置库是只读目录，不是持续控制用户选择

目录由现有静态库编译成去重ID、名称、来源关系和已验证类别的索引。资源类型叫 `buff` 不等于效果一定是正面Buff；静态未知极性进入 `Auto/待分类`，实际Buff/Debuff来源及人工覆盖依当前分类规则判断。隐藏来源和正负面类别也是两个维度。空职业库显示暂无数据，不补虚构条目。

用户一键导入应走：所选包 → 去重与容量预检 → 更新用户集合 → 一次保存事务及回读 → 已提交集合的可见展示。未知极性Auto也算已追踪；不存在于实时身上不是未导入。失败说明 plan/validate/commit/present 中哪一阶段失败；“已保存但刷新失败”不能说成没保存。

重复导入不重复；取消后重载和插件更新不会自动加回。主动重导某包可以重新选择该包，但普通后台升级不能擅自替用户决定。对“补齐新版”这类概念说明新增条目范围，不能让新用户先逐职业操作；本轮常用界面已移除该按钮，但内部兼容方法不是必须删除的代码。

大量ID保存的物理表示与损坏拒绝见[存档](persistence-and-diagnostics.md)，不能仅用UI切页掩盖保存丢项。

## 图标链路：不要把占位图缓存成成功

检查目录ID → 元数据请求 → capability → Native返回 → 缓存 → 通知事件 → 当前可见行绑定的完整链。

分别表示：未查询、等待、真实图标、确实无图、暂不可用、接口错误、占位展示。占位资源不作为正缓存封锁后续真实读取；暂不可用也不能变成永久无图。已知真实图标优先，负缓存有边界和恢复机制。

`nativeLookups=0` 只说明该统计范围没有执行查询，不能解释成“API返回空图”；`active=false` 可能因为打印时已离开库页。联合requests、cacheSkips、inactiveSkips、queued、batches、returnType及其生命周期判断。只保留少量返回形态，不缓存完整tooltip正文作日志。

只对可见行排队并分批查询；使用现有scheduler、缓存与更新事件。不在每行render或50ms遍历整库请求Native。通知签名必须读真实EventBus；回调收到owner却当reason会让结果留在缓存、界面一直不刷新。池化行用绑定代次防止旧图标串行，详见[回调契约](callback-and-request-contracts.md)。

## 小窗、大页与性能验收

小窗默认当前状态，给出来源/类型、留存和已追踪切换，行操作通过同一Commands保存。大页保留内置库、导入导出和复杂HUD设置；两者不是两套真相，也不把数百项收藏固定当实时HUD。

投影按revision、筛选和绑定身份更新；虚拟化只渲染可见行，稳定排序末尾加ID。真实接口未提供图标、单位或CD时保留未知，不能猜图片路径、拿技能ID当效果ID或用静态秒数冒充冷却。技能CD属于独立技能事实与生命周期，不借Buff时长推断敌人CD。

最小回归：开启后才出现的短状态、消失后留存、目标切换、容量溢出、清空但继续、关闭单窗、功能停用/重载释放；HUD不受留存影响；批量保存/失败回滚/取消后重载；真实通知刷新；占位缓存恢复、图标能力恢复、池化旧结果拒绝。

## 自己装备、敌方类型、职业图标不能混成同一种数据

自己实际装备走已验证装备槽读取；无法查看敌方物品时，只能基于当前目标的已观察状态显示装备类型。用户本轮提供716皮甲、4899双持、8226盾牌、8227双手，已与当时项目映射对照；这些是该案例输入，不是跨版本永久ID表。不得把类型Buff推断成具体武器名称、品质或伤害；同类型换另一把武器时图标不变不一定是故障。

装备类型由业务语义选择，不要求用户先把这些Buff加入个性化追踪列表。目标换人或读取未知时，不能借用自己的物品图或上一目标图补齐；冲突状态要有明确降级。图标优先当前Buff元数据，没有合法资源不发明路径。维护映射仍走项目ID中心，不在UI散布常量。

职业类别图标不等于每种三天赋组合独有职业Icon。遵循项目现有分类与来源证据；未知组合保留文本/未知，不强行猜近战远程。新图标需进入完整校准/保存/导出/默认恢复链，见[HUD模板](hud-template-and-defaults.md)。

“元数据查到了图标”与“Native纹理已显示”是不同缓存：明确拒写时不要更新已渲染路径，持续失败不能无限留旧事实。[PVP契约](pvp-hud-and-freshness.md)给出失效、提交和有界重试要求。
