# 今日总览第二轮：卡片工作台、任务操作、目标详情

日期：2026-09-12  
补丁标识：`overview-workbench-2`  
基线：本次对话原包及已交付补丁，最后一包为 `ReplicatedSuite_CompactTracking_TradeBudget_Overview_2026-09-12.zip`。

## 1. 本轮完成内容

### 首页布局

把原来的大段说明、散放收益字段和“上一行/下一行”改为固定层级：紧凑标题/统计日期、四张有测量能力的统计卡、两个命名页签、独立内容卡。页签为“活动与跑商”和“任务与居民板”。宽度足够时同页两列；内容宽度不足820时展示一个卡片，并出现明确的活动/跑商或任务/居民板切换，不再用没有业务含义的行号隐藏内容。

卡片使用现有 GroupBox 和 RSUI 测量/布局，不通过装饰 Border 拼接未测量子控件，不复用或移动已创建悬浮窗。统计项没有合法数据源时显示“—/待接入”，不是伪造的0。活动列表、跑商路线和居民板继续用原有 Feature 数据，不增加第二套采集逻辑。

首页跑商只显示三行常用操作，扩大搜索留在完整跑商页面和原悬浮窗。当前批次执行中，同一个询价按钮变为“取消询价”。原有限批次、品质策略、缓存和取消逻辑不变；打开/刷新首页不会发送询价。

### 任务区

新增 Feature 的 `GetOverviewProjection`：从现有 Authority 缓存取得日常和周常父任务，建立仅一份 revision+条件的会话缓存，不在搜索或表格绘制时调用 Native。支持日常/周常/全部、已追踪/全部、未完成/可交付/已完成筛选，以及名称/分组搜索。

提供明确的“搜索/清空”按钮，不依赖客户端 Enter 事件。点击行只选中，不自动弹出详情；“加入/取消追踪”通过原 Commands 保存；“任务详情”才打开详情窗口。未获取到进度的任务不会伪装成已完成。展开子任务不重复计为父任务组。

切页、窄屏切卡和隐藏页面时结束合法输入草稿，释放键盘，不能把编辑框留在隐藏页。即使 PageHost 在首次测量前激活页面，隐藏任务卡也不会取得消费者。不同窗口的消费者互不释放。

### 官方新增的目标文本入口

RU 官方2026-09-09更新公告明确开放：

- `X2Quest:GetQuestJournalObjectiveCount(idx)`
- `X2Quest:GetQuestJournalObjectiveText(idx, objIdx)`

原始来源：<https://ru.archerage.to/forums/threads/obnovlenie-09-09-2026.17558/>

仅根据此声明更新这两个能力和开发参考，未放开收益相关接口。`OfficialEnabled` 不等于当前客户端返回形态已经验证。

显式打开任务/活动详情时，QuestProgress服务按当前活动任务索引读取目标文本。读前、读后都核对索引对应的任务ID，防止任务日志重排串到其他任务。只接受有限非负整数数量和纯文本返回；不解析目标文案中的数字作收益或完成计数。类型不符、数据超限、索引变化或能力不可用都返回明确原因，原分组完成进度仍独立保留。

每次详情最多读取4个不同的已接任务，每个最多16个目标，每个文本最多2048字节；超限整体拒绝该任务或明确标记未读数量。最多16份缓存，3秒TTL，任务刷新/服务停止清空。平时任务表格刷新不会读取这些新接口。诊断只输出返回类型、次数和失败原因，不二次读取目标文本。

索引与返回类型的真实RU表现仍需实机确认；本次只完成有严格边界的适配和合成接口回归，不声称所有任务的目标文本已在客户端验收。

### 今日统计账本修正

`GetProjection()` 改成纯读，不再在首页每次刷新时读取服务器时钟、触发日期轮转。日期仍由原5秒低频任务和接收合法观察时检查。

修复服务器时间读取失败时，把错误字符串误当日期显示的问题。暂停后显示账本保存的日期，不把旧数据标成新一天。已有验证源的已累计数值，在同日重载重新定基线前继续标为“已保存/有间断”，暂停时保留真正记录的合计。接口缺失不凭空产生0。

**尚未完成：金币、荣誉、经验、生活点四项实际数据源。** 本轮没有新增这些Native读取或把聊天文案当作事实。没有有效来源的通道仍显示待接入；不能把账本测试通过说成实际收益功能已经可用。

## 2. 文件与兼容性

仅交付实际改变文件，保留 `replicatedsuite/` 和 `z_api_functions/` 相对路径。没有删除。开发参考本轮确有两项官方增量，因此不是“API文件未改”：`api_functions.lua`移入两个已开放方法，同时新增本次增量说明。

`toc.g`不变，所有运行时修改落在已加载文件中。没有修改公共Persistence算法、Transport 3/4、已有业务Store schema、恢复白名单、旧档指纹、换装保存、状态追踪和持续留存。没有新增用户配置迁移，没有删除现有方案。

同一天暂停/恢复统计不清账。统计停用时不轮询时间；启用后再按服务器日期归零。没有用本机日期代替服务器，也不会把无法归属的离线变动补记到新一天。

## 3. 性能及资源

没有新增Tick、周期任务、事件类型或拍卖查询循环。首页复用既有事件合并刷新；隐藏工作区释放自己的Feature需求，不影响其他悬浮窗。任务筛选有一份会话缓存，不逐帧构建全部任务行。

新任务目标读取只在用户显式打开详情时执行，最坏为4×(1次数量+16次文本+2次索引身份核对)=76次轻量Getter；缓存命中只核对索引身份。总缓存正文理论上限16×16×2048字节，外加少量表结构；服务停止清空。单次Native调用实际耗时尚未在RU测量。

账本原有5秒时钟检查保留，首页读模型取消重复Native时钟调用。没有四项余额/经验的隐式轮询。
