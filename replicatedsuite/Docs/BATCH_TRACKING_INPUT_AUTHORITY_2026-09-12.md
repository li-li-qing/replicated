基线：Addon(20260912-025223).zip，加至 Gear_Plan_Editor_Fix 的本会话增量包。
本次只修改 3 个运行时文件；不修改业务 schema6、旧档恢复白名单、业务指纹算法、HUD 生命周期或导航完成状态。

## 实际报告

报告 ID=1.2 显示 B2/W1：

- 推荐库候选含397个auto状态，但提交阶段失败：`04287DD8>3AF652D5|divergence=$.settings.tracked.auto.189: type number vs nil`。

## 输入草稿根因与修复

编辑框原有合法Native输入草稿与Diff缓存的已提交空串不同。新建成功清空、或取消编辑回到相同已提交值时，缓存命中路径读取Native差异，误将合法键入记为外部修改。

`UI:AdoptInputDraftText`只在未退役、已在private armedInputs登记的键盘输入控件、且owner匹配时，将当前文本接回Diff快照。Disarm前交接一次；SetText缓存分支有同样的合法交接保护。不提交Binding、不提交Store、不接纳其他属性，也不清零过去的违规计数。未激活输入、普通控件和错误owner继续严格检查。

## 批量保存：Transport4显式选择

使用真实Store/Catalog/Feature实现，加一个“Native丢弃数字键>=189”的故障模型，旧代码精确产生与用户报告一致的两组Hash和首差异路径。这是可复现的数据丢失模型，不能据此宣布RU全平台存在固定188项上限。

新格式只改变跨SaveData边界的物理表示。Core默认写入版本仍为3；仅`v3.buff_display`注册`transportVersion=4`。旧版本1/2/3继续读取。

Transport4继承Transport3的布尔、空值和精确数字保护：

- 连续正整数序列33..2048项，拆成16个ID一段的十进制短字符串；值域1..16777216。
- 分块表包含计数、标记与p1/p2...字符串键；不把397个数字索引原样交给Native。
- 每串最多143字节；最大2048个ID对应128段加2个字段。
- 数量、字段集合、段号、每段长度、整数格式全部严格校验后才能还原业务数组。
- 缺段、截断、额外字段或非法转义直接拒绝；内容改变仍须被原来的整份业务指纹拒绝。
- 小数组、稀疏表、非ID数组不强行转换；保留前缀的原生用户文本/键进行转义。
- 仍检查逻辑、编码及物理预算；仍一次事务/一次正常写入与耐久回读。不是分多次追加保存，不降低追踪上限。

## 首次安装的旧会话保护

新代码尚未加载，无法撤销此前旧代码已经做过的物理写入。失败事务已将当前内存回滚，但Native可能保留了缺项的新写入。

在本次报告所示“状态显示仍可打开、没有加载写保护”的旧会话中，建议**先进入状态显示 → HUD布局 → 调整HUD → 保存并退出**，不必改位置。这个已有入口执行force/durable整份配置保存，保存的是当前经过回滚的配置，不是新生成的默认值。提示保存成功后，再覆盖补丁并使用插件内“重新加载文件”，随后重试推荐库导入。

该入口已用尾部丢失模型验证：失败397导入 → 内存回滚 → 已有HUD保存入口恢复原配置到物理盘 → 全新加载一致。它不会帮用户重新加入失败的397项；加入操作在新代码加载后重新点击。

如果用户已经重载成写保护页，此流程不能越过保护。不要清档、重置、改Hash，也不要用旧UDF覆盖当前用户改动。需要保留新的失败原档再定位。

## 兼容与性能

业务schema6、保存键、指纹算法、旧数值精度恢复不变。Transport4保存后，旧Core（最多支持3）不能读取；回退必须匹配代码和配置备份。

不新增Tick、计时任务、事件通道或后台全库扫描。输入交接只多一次短文本读取；物理编码/解码在已有Save/Load冷路径执行，临时分块受2048项上限控制，沿用原有存档预算。

单元测试不能保证Native所有隐藏容量限制：若客户端仍破坏新分块，必须保留保存失败，不接受不完整追踪列表。
