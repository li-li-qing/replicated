## Evidence rules

- `IMPLEMENTED` requires a real user-action/read path through Feature/Service authority, state/projection change, and presentation refresh.
- `PARTIAL` means some of the behavior exists but the advertised user capability is incomplete.
- `TODO` means the capability is in product scope but has no safe current implementation.
- `SPECIFIC_RUNTIME_BLOCKED` is permitted only for a concrete missing/unknown RU API contract. The blocker, current implementation, searched evidence, and exact RU test are recorded below.
- **Locked-row rule**: Do not delete or downgrade rows to make a gate pass. A row may change status only on explicit user removal or `MERGED_WITH`; it may become `SPECIFIC_RUNTIME_BLOCKED` only with the exact API/legacy/search/test evidence recorded below. Capability evidence is locked in this matrix (rule merged from the 2026-08-31 autonomous continuation checkpoint; original checkpoint file archived to `Docs/Archive/Handoff/AUTONOMOUS_CONTINUATION_20260831.md`).
- `UNREVIEWED` means the current and legacy evidence has not yet been audited; it is not completion.
- Local Lua/harness evidence proves code contracts only. It does not prove RU native construction, returned-field semantics, visuals, or multiplayer performance.
