# F2：页面隔离与原始文件取证

日期：2026-09-12。基线：本对话 `Addon(20260912-025223).zip` 及之后至 `ReplicatedSuite_Status_Death_WindowPrecision_2026-09-12.zip` 的七层增量（两按钮、交付、容量、回读、聚焦、跑商精度、F2窗口精度）。

## 本轮不做的事情

不扩大数值候选，不放行用户 Hash，不清档、不重置默认值，不改 Store schema/Transport/指纹/迁移。
用户实际的状态显示和死亡回顾原档还未取得；不能声明 F2 已恢复。

## 1. 已修的页面故障

`rs_v3_death_review_page.lua` 原来在 Build 创建持久化 Toggle 后，才在 OnActivated 调用 EnsureStoreLoaded。
实际 Binding 在创建时 PrepareRead，写保护因此被放大成页面构建失败。
现于第一项业务控件之前准备 Store；返回失败、抛错、缺失入口均转入只读保护页。
保护页不创建编辑器、删除/清空按钮，不调用业务命令、不订阅、不读记录分片；进入/离开页面不重复读盘。
导航仍经过 V3 Host；真正的控件构造错误仍由 BuildScope 处理。保护页不自动清除任何写保护。

## 2. 诊断文字纠错

Core 原来进入窗口数值枚举就记录 `tested`，即使候选过滤后 attempts=0。
现在只有实际计算候选指纹才标 `tested`；没有可区分候选标 `no_alternative`。
这只是状态描述修正；候选集合、步长、次数、范围、返回值与恢复规则均未改变。

## 3. 为什么改用文件取证

本次两个故障被短报告标记 `raw=0/2 rawStatus=copy_budget`。这表示程序没有附原档，不是用户复制丢失。
任意长度的数据库不可能无条件无损地塞进3,500字节控件。此后超限报告明确给出 `next=udf_snapshot`，
页面提醒不必重复相同摘要。仍保持两个游戏按钮、短报告上限和一次 Native 样本读取，无后台采集。

本项目既有 `Docs/README.md` §6.2 曾记录磁盘目录为“文档/ArcheRage/USER…/udf”。
该记录是目录线索，不是本轮已读取用户磁盘，也不意味着每台机器有同一路径；用户需确认当前账号目录。
本轮不根据 README 中的 RocksDB 描述猜文件名/记录格式、不筛选扩展名、不只取某个看似相关的数据库文件。

## 4. 离线采集页使用

文件：`replicatedsuite/tools/rs_udf_evidence.html`，单文件，开发工具，不进入 toc.g。

1. 完全退出客户端。可先将当前账号的 udf 文件夹复制到别处作备份。
2. 用桌面浏览器打开该 HTML；选择当前账号的 **udf 本身**，不是整个 USER、Addon 或游戏目录。
3. 查看相对路径/大小列表，确认客户端已退出和隐私范围，点击“生成本地取证 ZIP”。
4. 生成成功后点击“保存取证 ZIP”，保存到下载目录等非 udf 位置，再作为附件发给维护者。

也可以完全不运行采集页：退出客户端后，用操作系统压缩当前账号的整个 udf 文件夹，再提交 ZIP。
无须为取证更新游戏代码后再次启动客户端；已有失败配置文件就是本次所需样本。

### 隐私、权限与数据边界

- udf 可能包含其他插件配置、角色名和历史。工具不能只解析两个 Store；确认后包含浏览器提供的全部所选文件。
- 不自动上传。无联网依赖、fetch、远程脚本、系统 shell、剪贴板、数据库写接口或安装步骤。
- 文件内容按二进制原样存储，不重新序列化、不压缩、不运行文件内容。零字节文件也保留。
- 文件 SHA256、ZIP CRC32 仅用于复制核验，不是游戏完整性校验，更不意味着恢复成功。
- 超过2,048文件/64MiB总正文、路径异常、读取失败或长度变化时整体拒绝，不生成缺文件ZIP。
- Browser FileList 无法独立证明目录枚举完整，不能检测所有权限拒绝/不可见项。
- 用户确认已退出客户端不是进程检测；这是用户选择的文件集合，不是数据库在线原子快照。
- 输出可能仍含敏感信息且未加密，请勿公开分享。不知道该分享哪个账号目录时先不要上传多个账号。
- 输出只含相对 udf 路径，不主动收集 Windows 用户名或绝对路径。
