# 当前发行入口：RS-FOCUS-1 单次故障报告

本节取代下方旧版本对“默认打印”的描述；旧完整报告及分段协议仍保留为内部维护兼容能力，不再是普通玩家需要执行的流程。

## 实际反馈与范围

用户提交的 `RS-REPORT-PART-2 ID=1.1 PART=1/10` 数据段为 3821 字节，Adler32 为 `6335BDC4`，单段校验通过。它是报告的第一段，不是整个报告，不能从这段重建剩余九段，也不能据此宣称已拿到三个存档的原始数据。原文声明 107216 字节，复制包共37059字节。首段可展开的前缀已出现正常 Store 的详细预算行；代码同时输出完整 Persistence.rows、Acceptance、所有 Provider 和日志，使真正需要的故障字段被大量重复状态淹没。

## 两按钮与默认行为

- **运行自检**：沿用 Gate 的 `skipSequences=true`，只检查，不执行修改状态的验收序列，不清错误环，不读取故障存档原档。
- **打印自检报告**：调用 `PrintFocusedSelfCheckReport`，生成至多3500字节的 `RS-FOCUS-1`，默认1/1，一次全选复制。后续再按打印生成新的报告，不推进旧分段。

主体是单行可读字段，原生编辑框自然换行显示。开头是 `RS-FOCUS-1`，末尾是 `RS-FOCUS-END ID=...`。摘要包含版本/运行时、当前阻断警告、失败检查、完整成组指纹及本次加载以来已记录错误。重复错误沿用现有聚合次数；正常 Provider 的全量转储与重复信息不进入默认报告。

报告的摘要有固定容量，不能容纳任意数量的完整错误栈。`storeOmit/checkOmit/historyOmit/clipped/evicted/preclipped/captureFail/logDropped` 明示覆盖范围和损失。它不是“所有错误与所有原档均完整”的承诺。未记录、重载前和其他插件/客户端内部未暴露的错误仍不能补回。

## 一份可选的完整原始样本

候选仅来自已写保护 Store。优先同 schema、无自定义 codec、较小声明预算；这是排查样本选择，不是根因认定。本次三个故障组合优先选择 `v3.life.trade`。

最多进行一次 `BuildFailedStoreEvidenceText(id,{compact=true})`。Core 仍负责 scope、SaveKey、能力门、表深度/大小检查；不调用 LoadStore/default/decode/migrate/apply/Save/Clear，不改指纹或 Fence。

`compact=true` 只移除取证**外壳**重复的 key/failure/build/capturedAt 等字段，保留 `store` 与整张未经解码的 Native `raw` 表，包含原有 `__rsmeta`。旧无参方法仍返回原完整外壳。该样本是本次 Native LoadData 返回值，不是磁盘原始字节、不是首次故障时的备份，也不是可信恢复数据。

只有整份样本编码包能放入总预算，才附加 `RAW_BEGIN ... RAW_END`。大于16384字节的原始取证正文不压缩；超限、读取失败、编解码不可用会留下原因并整份省略，不自动加页。`raw=1/3` 只表示附带了3个故障中的1份，另2份未读取/未包含；`raw=0/3` 表示本次没有附上原档，不能靠摘要反推缺失内容。

保留原 `RS-REPORT-COPY-1` 作为可选样本内部编码，映射其中的外层LF为`~`。正文不再整体编码成十段。封装只是复制校验，不是加密；可能包含角色信息，禁止公开发布。

## 交付边界

3500字节是低于用户已成功提交的3963字节片段的保守目标，不是所有客户端的容量保证。先完成共享布局/可见/焦点事务，再 SetText/GetText 精确回读。当前协议不含字面CR/LF，允许编辑器插入显示换行，空格及其他语义字节仍需相等。低于容量或回读失败仍返回失败，不截图假装成功，不调用禁用的剪贴板API。

完整校验覆盖 `BODY_BYTES` 与 Adler32 `CHECK`；不可把它当密码学认证或存档业务指纹。聊天 `RS-CHECK-4` 仍只是一条回执，提交内容来自报告框。

旧大报告测试仍保留；测试宿主显式注入旧全量源，不能将旧大报告的通过数量冒充新默认已实机验证。新默认覆盖真实 Store/Core 与模拟4096字节、删除换行的编辑器，并逐字节比对compact/raw与原完整取证的raw相同。运行环境与实测边界以交付测试记录为准。

# 自检报告：以实际文本回读决定交付（2026-09-12）

## 当前基线、证据与结论

本轮基于 `Addon(20260912-025223).zip`，依次覆盖已交付的两按钮统一自检、报告显示修复、容量分段补丁。最新实机截图是：报告 107192 字节，`RS-CHECK-2 ... view=failed code=TEXT_READBACK`。当前源代码在写入后发现 `GetText` 与发出的段不一致，就清空输入框；没有记录写入/读取长度、首个差异或调用失败类型。

**截图只能证明报告编辑框未通过往返校验，不能证明 Native 具体是按更小容量截断、改变换行、返回了非字符串，还是接口调用失败。** 本轮不声称查明了实际客户端的转换机制，也不将合成接收端测试当作客户端实测。已确定的实现缺陷是：把声明容量当作交付预算，一次不一致就放弃，缺少基于实际回读的适配；并且在回读之后才执行焦点/布局操作，无法保证这些原生操作不再改动文本。

本包修正上述交付流程，并让下一次失败的同一条回执携带实际边界数据。没有修改存档或宣称三个 `F3` 已恢复。

## 当前行为

页面仍仅两个按钮：**运行自检、打印自检报告**。

1. 首次打印按原规则生成一次报告、对每个失败 Store 读取一次取证，保留同一份不可变正文。
2. 先通过共享 UI 布局、可见性和输入激活接口，再写入当前段并回读；不在验证成功之后再激活焦点。
3. 原协议能精确回读时继续使用原文、`RS-REPORT-COPY-1` 或 `RS-REPORT-PART-1`，不无故更换格式。
4. 首段尚未显示成功时，如果真实回读失败，则自动试无硬换行的 ASCII `RS-REPORT-PART-2`；仍不一致则依据回读结果/减半缩小预算。每次点击最多 8 次有界写入与回读，最低预算 512 字节；不以“写入没有抛错”或“长度相同”代替内容相等。
5. 换行/空白容忍仅用于新协议的外层 ASCII 编码。原报告、UTF-8 字段、证据中的原始字节及所有业务指纹不变。
6. 只有完整的当前段通过比对才提交段号。后续打印使用同一份报告和同一套分段，不重新自检、读取 Store 或压缩。已经交付过任何段后，不再自动重新划分段落，避免旧 `1/N` 与新 `2/M` 混用。
7. 多段需收齐全部；末段后再点打印回到同一报告第一段。运行自检或离开页面会释放正文、编码副本、段号、重试状态与键盘占用。
8. 抛错、明确返回 `false`、非字符串返回等接口失败不当作容量问题无限重试；仍然失败时仅保留内存快照，清除未经校验的 Native 残段，不声称报告已交付。

当前 `MaxTextLength()` 的返回值只是初始声明值，**不代表真实接收容量**。同样，回读成功只说明该时点的编辑框内容可重建当前段，不等于已验证操作系统剪贴板。

## 复制方法

覆盖并重新加载文件后，点“打印自检报告”。在下方框内 `Ctrl+A`、`Ctrl+C`，粘贴到记事本。若显示 `1/N`，再点同一个打印按钮，逐段追加到同一文件，最后提交 `.txt`。

新协议可能显示成一条自动折行的长串，以 `RS-REPORT-PART-2;` 开头。不要手动整理分号、波浪号、数字或编码。全部原始数据仍在其中，不是短摘要，也不是加密。复制期间不要切页面、点“运行自检”或重载。

若仍失败，聊天唯一回执以 `RS-CHECK-3` 开头，会带例如：

```text
rb=8722/4096@4097 cap=9215 try=1 wire=legacy w=ok g=string hex=41/EOF
```

以上仅为字段示例，不是本次用户的真实取证。`rb` 是写入字节/实际返回字节，`@` 是按协议处理外层换行后首个不同字节的位置；`cap` 为当前交付预算；`try` 为本次尝试次数；`wire` 为协议；`w/g` 为写入和读取结果；`hex` 为差异处字节的十六进制值，`EOF` 表示已到末尾。回执不包含原始存档正文或角色名称。只需复制这一条，就能区分原来都被掩盖为 `TEXT_READBACK` 的边界问题。

## 协议与维护边界

### 旧格式保留

`RS-SELF-CHECK-1` 原文、`RS-REPORT-COPY-1`（LZB1/RAW64）、`RS-REPORT-PART-1` 仍可解码。业务 Store、指纹算法、迁移、序列恢复、写保护和能力门均未改变。

### 新格式 RS-REPORT-PART-2

固定 ASCII 外层：

```text
RS-REPORT-PART-2;ID=...;PART=i/N;TOTAL_BYTES=...;TOTAL_CHECK=...;OFFSET=...;DATA_BYTES=...;DATA_CHECK=...;DATA=...;RS-REPORT-PART-END
```

DATA 来自原 `RS-REPORT-COPY-1` 编码包的一段，仅将 LF 转义为 `~`。原编码包的固定头和 Base64 字母表不含 `~`、分号或空格，故这是一一映射；原报告中的真实波浪号、分号、换行和空格已经在无损编码中，不参与替换。外层只允许忽略 ASCII 空格、Tab、CR、LF；不忽略 Unicode 空白或任何其他字节。

解码先还原原包片段，再验证段身份/索引/偏移/字节数/段校验/整包校验，最后由已有 LZB1/RAW64 解码器还原原文并复验。Adler32 检查复制损坏，不是身份认证。缺段、混入另一报告、修改内容、矛盾重复、非法长度或非空白变化全部拒绝。新旧分段不得混用。

`tools/rs_report_copy_decode.py 输入.txt 输出.txt` 同时接受旧格式与新格式，拒绝覆盖已有输出文件，不执行 Lua、不写游戏文件。用户不需要自行运行工具。

## 性能、所有权与安全

- Diagnostics 仍拥有报告，Presentation 拥有 Native 交互、确认段号、输入焦点和页面生命周期。Transport 只处理有界编码/分帧/比较，不访问 Native 或磁盘。
- 编码复用，预算重试不重新压缩；只保留本次原报告和一个编码副本。不驻留所有分段字符串。
- 新行为仅发生在显式打印点击中，无 Tick、轮询、后台任务、全局输入钩子或新按钮。
- 不调用不允许的剪贴板接口，不尝试绕过 API 门。允许的 Native 方法已对照 `z_api_functions/ui_functions.lua`，实际返回行为仍以客户端回读为准。
- 原容量边界仍保留：报告最多 1 MiB、分段最多 256、每段预算最多 32 KiB；超出可交付预算必须明确失败，不能删除证据冒充成功。

## 离线验证与限制

新增 8 项 Lua 回归在旧实现下全部失败，覆盖声明 9215/实收 4096、删除换行、外层空白、短原文无损转义、真实失败数据、接口抛错/拒绝、激活后清空及协商不重复编码/读盘。新增 Python 测试覆盖新协议逐字节还原、旧协议兼容与恶意/残缺片段拒绝。

三个真实 Store 的代码另经“声明9215、实收4096且删除换行”的联合合成接收端，验证协商和翻段过程仍仅三个 Native 读取，零保存/应用/清空，写保护保持。原编辑框等于声明容量的测试仍保留，但不再当作 Native 充分覆盖。
