# 跑商实际存档：数值精度取证与 Transport 3 修复

## 输入、验证与边界

本轮基线为 `Addon(20260912-025223).zip`，依次覆盖此前的两按钮自检、报告交付、容量回退、回读适配、聚焦报告增量包。实际依据是用户粘贴的 `RS-FOCUS-1 ID=1.1`。

外层 BODY_BYTES=3108 / CHECK=71AC05C7 验证成功；内层 LZB1 复制包解码为1797字节，内部取证 BODY=1725 / CHECK=03EC20DC。仅包含 `v3.life.trade` 一份完整 Native 返回表。不能从另两个 Store 的 Hash 反推其原始数据。

完整原始样本已转为静态开发期 fixture：`tools/fixtures/trade_native_numeric_20260912.lua`。仅含路线选择、窗口参数和元数据，无玩家标识；它不是客户端物理文件或保存前的内存副本。

## 实际证据

使用现有生产指纹算法（未修改）计算：

| 对象 | 结果 |
|---|---|
| 元数据封印 | `6C14E7A5`，与原档一致 |
| 当前跑商 canonical | `48B0E072`，与用户摘要一致 |
| 原档自带业务指纹 | `6BE9E557` |
| 仅将 `widgetWindow.normalizedCenterX` 的 canonical 数值改为 `0.0903896` | 整表指纹 `6BE9E557`，精确命中原档 |

Native 原值为 `0.09038999676704407`，在历史六位有效数字指纹中成为 `0.09039`。这是和恢复候选 `0.0903896` 不同的 token。

独立实验把候选整表所有数字先格式化为六位小数，再转为 binary32，逐字段得到用户提交的整张 payload。由此得到一个与证据完全相容的数值损失机制；本轮没有客户端 serializer 源码，不能断言其内部一定使用相同实现。

旧注释“六位有效数字一定抵抗序列化浮点变化”不成立。有效数字与小数位数是不同契约。仅重盖 Hash、减少校验精度、忽略窗口字段都不是本修复。

## 修改与安全边界

### 1. 物理 Transport 3

`core/rs_persistence.lua` 新写采用 `transportVersion=3`。非整数和绝对值大于16777216的整数（包括键）使用 `__rs_t3:n` 加17位往返十进制数字串，读出后还原为 number。安全小整数仍用 Native number；0、false、空串、空表及前缀字面字符串继续有明确编码。

这是传输表示升级，不是 Store schema 或指纹算法升级。读取1/2/3；显式历史编码仅用于兼容/回归。新写在原预算下执行，字符串膨胀超限在 Native SaveData 前拒绝，不扩大预算。非法数值串、非有限数、解码键碰撞、未封装风险数值和未知版本都拒绝。

读取 numeric token 时仅容忍科学计数法指数的等价补零，避免不同 C 运行库把 e-021/e-21 当成不同格式；尾数仍要求规范往返表示。

健康 v1/v2 不在启动时批量改写，下一次正常保存自然升级。精确恢复成功的旧档排队升级3，避免继续通过已知有损边界。

### 2. 跑商的受限旧数值恢复

`features/life/rs_life_m16_bundle.lua` 为跑商声明历史恢复函数。仅处理 Framework3/Transport2/schema1/integrity4，校验 Store/owner 和现有自由坐标语义。

仅考察 `widgetWindow.normalizedCenterX/Y`，每次只改变一个已有 number；范围限定为绝对值[0.01,1)且不跨数量级。根据相同固定六位小数表示生成有限六位有效数字 token，总计至多32次完整指纹验证。

**唯一整表命中**才返回候选；Core 继续验证 metadata、schema、预算和原指纹。实现不硬编码用户 Hash 或坐标、不动路线/收藏/开关/宽高，不更换为默认值。多候选、无候选、超范围、多字段联合精度损失等仍保护。禁止后续扩成任意字段暴力搜索或盲目增加次数。

恢复的是原指纹表达的六位有效数字；无法声称还原已丢失的全部17位原值。加载本身不写盘；成功后由正常保存流程持久化。

### 3. 死亡回顾的既有索引兼容

`features/combat/death_review/rs_death_review_store.lua` 原字符串序号恢复分支仅接受Transport2。新传输不改变序列键风险，因此允许已解码的2/3共用既有严格1..N重建，并保持schema/owner/codec门。

这项改动是回归发现的配套修正，**不是对用户当前死亡回顾 Hash 的恢复**。状态显示旧档也没有取得原始表，本轮不新增其数值恢复桥。
