# V4.1 跑商模块诊断复制与所选货物成本证据修复

基线：用户最新上传的 `replicatedsuite(4).zip`。本轮没有从更早的 Addon 包重建业务代码。  
诊断标识：`diagnostic-copy-selection-1`、`trade-selected-economics-1`。

## 1. 完成内容

### 1.1 模块诊断：重复聚焦可以破坏刚选中的报告

真实调用链是业务页诊断按钮 → ModuleDiagnosticsHub → ModuleDiagnosticsWindowV3 → DiagnosticCopyBox → 原生多行编辑框。它不是全局诊断页面的通用编辑框。

原来的独立 CopyBox 在每次 Activate/OnClick 都重放 EnableKeyboard(true) 和 SetFocus。生成分页已经主动聚焦，用户再次点击或结束文本选择又触发 OnClick，可能再次折叠选区。对比普通输入，普通输入已有“键盘已取得且焦点仍属于自己”快速返回，而专用 CopyBox 漏了这条保护。

本轮用真实 CopyBox 控制器，和会在 SetFocus 时折叠选区的原生边界模型复现。现在已取得键盘且焦点身份明确相同时，不再写键盘、焦点或选区。首次键盘提升仍会 SetFocus，即使原生提前发布了焦点 ID；真正失焦后，只有用户显式点击才重新激活。支持既有物理/逻辑焦点身份，不猜测未知窗口。

同时拒绝已销毁、普通输入已退役或旧 Generation 的迟到激活，避免关闭/重载后的旧回调重新取得键盘。普通输入的 DraftSession、换装名称输入、数值输入生命周期均未修改。

### 1.2 模块诊断：正文验证后再次聚焦，会使“回读一致”失效

原模块窗口的交付顺序是 SetPageText（含 GetText 回读）→ Activate/SetFocus；而全局诊断已经采用“先激活再写入验证”。现有全局报告回归也明确覆盖了焦点提升可能清理原生缓冲的边界。

本轮使用真实模块 Window + 真实 CopyBox 联合回归，只替换原生编辑对象。原顺序在“激活清空原生缓冲”模型下，第一页、翻页和焦点拒绝三例均会出现：正文已校验成功，但最终缓冲为空。现在统一为先激活、再写入并验证正文，验证成功后不再追加一次焦点操作。

焦点失败不伪报成功：仍交付完整文本并保留上一页/下一页，页脚明确提示点击文本区重试。Native 写入失败仍保留冻结报告，沿用有限次数的容量适配；没有通过无限 SetText、SetFocus、重采集或缩短丢弃证据来掩盖问题。

以上是可复现的代码调用顺序缺陷；原生焦点/剪贴板在离线环境中是边界模型，不能据此宣称所有 RU 客户端复制失败都已消失。系统剪贴板未被读取或验证。

### 1.3 复制失败证据进入共享模块诊断

新增 `[DIAGNOSTIC_COPY]`，读取现有窗口与 CopyBox 状态，不创建新窗口。窗口在 Generate 主动撤权之前先保存 `copyBeforeCapture`；采集失败隔离，翻页不重采集。

记录包括是否已取得键盘、焦点归属是否可读、重复聚焦跳过次数、激活失败原因、文本写入/回读次数及字节数。`clipboardVerified=false` 表示没有系统剪贴板验证能力，不是断言复制必定失败。再次生成时的焦点可能已因点击生成按钮而变化，因此它仍是边界证据，不是复原过去所有键盘事件的录像。

### 1.4 截图中 8金59银：确认了成本证据丢失，尚未确认哪个实际报价有误

截图为 `[地狱]保存特产 / 126% / 44金77银 / 8金59银`。真实列表最后一列对应 `profitCopper` 的货币文本，是毛利金额，不是百分比。

真实计算为：

```text
材料成本 = 所有计入金币成本的材料数量 × 各自单价之和
毛利金额 = 交货估算价 - 材料金币成本
profitRate = 毛利金额 / 材料金币成本 × 100
```

按截图省略铜位后的数字，44金77银减8金59银约为36金18银。因此首先要查的是这条货物为什么使用了约36金18银的成本，以及交货估算是否与实际路线/熟练度一致，而不是直接把减法、新鲜度倍率或某个材料单价改成猜测值。

当前安装的静态表对物品31861（Hellswamp Preserved Specialty）使用两项材料：物品30899（Orchard Puree）×200、物品14630（Mushroom）×15。它是上传代码中的配方事实，不是本轮联网核验过的 RU 最新原生配方；真实截图当时使用静态还是原生配方，仍应以新诊断确认。

在 `BuildTradeMaterialProjection` 查到确定的作用域错误：`priceMeta` 在定价 else 子块内声明，材料行创建却在子块之外读取。正常全局不存在同名值时，单价、成本和毛利仍然参与计算，但 `priceSource / priceFreshness / priceAgeMinutes / priceRefreshing` 丢失。若存在无关同名全局，还可能混入不相干的来源信息。

本次只将 priceMeta 放回每项材料的正确局部作用域。持久价格缓存优先、会话报价回退、缓存保留及后台重验策略均不变。材料详情现在能展示原本已实现但因元数据丢失而缺少的缓存年龄。没有清缓存、调整币值单位、改材料数量、改配方表或改售价/毛利公式。

**不能把这一修改等同于“截图的8金59银已校正”。目前缺少该时刻的每项材料单价及来源、路线目的地、熟练度输入和原生交货对照。**

### 1.5 增加所选货物的只读经济明细

`Trade:DescribeSelectedEconomics()` 注册到既有跑商模块诊断，输出 `provider.describeselectedeconomics`：

- 所选 rowKey、物品 ID、来源/目的地区、真实与显示货率。
- 配方来源、配方名称、身份状态。
- 以铜为单位的售价、材料成本、毛利、算术差额及绑定/非市场成本口径。
- 售价基价、熟练倍率、品类/新鲜度倍率及来源。
- 最多32项材料的 ID、等级、数量、单价、小计、价格来源、缓存年龄、刷新状态。超过展示上限时明确计数，不假装完整。

诊断只读取当前已展示行，不重新访问 MaterialPriceService、不发拍卖查询、不请求原生配方、不取得 Consumer、不读写存档。没有选择行时明确提示 `select_trade_row`，不会把第一行或“最后一次报价”冒充截图货物。32项材料用有界证据字符串避免嵌套序列化节点预算吞掉后半项，测试覆盖了真实 Hub 输出。

## 3. 性能影响

复制交互只在显式点击/生成/翻页时进行，新增焦点身份读取有界；同一焦点不再重复写入。没有新 Tick、OnUpdate、定时器或剪贴板轮询。

业务材料刷新仅恢复原本计划携带的来源/年龄字段和详情短文本；没有增加价格读取次数。所选经济诊断只在用户生成报告时投影至多32项材料，未选择则立即返回。内存仅保留当前输入状态与固定分页快照，没有增长的键盘历史队列。

没有客户端 CPU/FPS/内存采样，不提供未经测量的性能收益数字。

## 4. 兼容与安装

这是对用户本轮之前上传的完整 `replicatedsuite(4).zip` 的增量修复。退出游戏并备份后，将补丁里的 `replicatedsuite/` 合并覆盖到 Addon 下同名目录。不要先删除整个旧目录，不要清存档或材料缓存。首次覆盖后完整启动客户端。

版本文字仍可能显示 `.18.332`，本轮没有擅自调整 V4.1 的主版本与构建号。可在模块诊断核对 `diagnostic-copy-selection-1` 和 `trade-selected-economics-1`。

本次不承诺修复外部剪贴板软件、输入法、客户端焦点实现等尚未取证的干扰，也不把系统剪贴板当成可读取的已验证来源。
