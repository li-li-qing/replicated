# Replicated Suite：重载／重登悬浮窗口位置专项修复

日期：2026-09-30  
补丁标识：`ui-position-reload-1`  
基线：`Addon(20260929-172837).zip` + `ReplicatedSuite_20260930_RefactorReview_Fixes.zip` + `ReplicatedSuite_20260930_LiveContract_Blockers_Fix.zip`。不是根据另一份未知本地工程制作。  
结论：发现并修复两类共用位置恢复缺陷；离线回归通过。真实 Lua 5.1 编译门禁仍为 BLOCKED，RU 客户端未运行，不能把本报告当作实机验收。

## 1. 完成内容

### 1.1 分辨率不变时，原生窗口发生偏移却不恢复

原调用链：`Runtime:Start` → `Layout:StartMetricsEvents` → 生命周期信号／已有 8 次延迟检查 → `Layout:PollChanges`。原实现只有度量签名变化才调用 `ApplyResponsivePresentation`。如果原生窗口的位置在启动／重载期间被重置，而 UIParent 尺寸、缩放及其它签名值不变，全部延迟检查都会跳过布局恢复。

离线故障模型在窗口已创建并正确摆放后，直接改变 Native 控件的坐标，不改变保存数据、不改变视口。原代码不能恢复；也复现了最后一次延迟检查才出现偏移的情况。这证明代码缺少这条恢复路径，但不能单凭该模型断言用户客户端就是以同一时序重置窗口。

修复：在原有生命周期边沿和原有有界延迟检查中增加独立几何核对。只检查已经创建、可见、没有活动拖动／缩放／几何租约的窗口，比较最后成功提交的逻辑矩形与校准后的 Native 实际矩形。有差异才通过原 `Windowing:ApplyGeometry` 重放同一矩形；不把 Native 观察值写成用户配置。

主窗及共用 WindowShell 通过现有 Windowing 绑定参与。R 入口、换装快捷按钮、功能方案快捷按钮通过现有 Floating／ScreenSnap 注册表显式加入，由各自拥有者报告拖动状态。Core 不访问具体 Feature，不重新扫描换装方案，不执行功能方案切换。

### 1.2 缩放／像素级度量变化，被旧中心坐标放大成明显位移

原 `ResolveWindowPlacement` 把 UI Scale 变化也视为需要中心比例重投影。保存记录中的中心可能来自展开窗口，而当前恢复的是最小化图标；把旧中心减去当前半宽，会额外改变左上角位置。

另外，原逻辑视口判定阈值只有 0.5。离线回归中，保存视口 1280×960、UI Scale 0.8，展开后再最小化，仅把 UIParent 度量改成 1279×959，就把 X=300 算成约 X=431.6016。该数值来自测试夹具中的实际共用窗口代码，不是用户实机截图坐标。仅 1 单位的度量变化却造成约 132 单位的右移，不是正常的边界夹紧。

修复：分别判断 UI 缩放变化与逻辑视口变化。逻辑画布不变，或者只存在约一个原生像素的舍入差异时，继续使用保存的逻辑 x/y，不因缩放或舍入重新套用旧中心。真正的跨分辨率变化仍保留原中心比例投影；安全边界、窗口尺寸拟合、旧边锚点配置及旧绝对坐标的兼容分支仍保留。

没有添加统一减 X、按固定 0.8 再除一次、恢复默认位置等补偿。

### 1.3 原生拒绝、用户拖动与迟到回调的边界

只有写入被接受且实际位置回读确认，才记录恢复成功。原生拒绝或假成功会保留失败原因。回滚本身可能回到偏移位置，因此同一个 Native 缓存行只暂存尚未完成的恢复请求，供已有的有限检查重试；新的布局／用户提交、真实几何租约结束导致的缓存清除，以及成功恢复会取消该请求。

特别补测：原生自己延迟恢复后，不能只清掉重试请求却留下错误的回滚缓存，否则下一次检查又会把正确窗口推回错误位置。已修正这一镜像重新确认边界。

不接管活动拖动，不强行显示隐藏窗口，不碰已解除绑定窗口。保留原 generation／epoch／serial 隔离；停止后旧回调不能移动新一代窗口。无变化时不调用恢复写入。

### 1.4 普通分页诊断增加位置证据

普通自检报告现在增加 `[UI_POSITION]` 和逐窗 `[UI_WINDOW]`，模块自身的位置诊断也能读取共用几何证据。

记录内容包括：当前环境及 UIParent 原始尺寸／原点、已有窗口的保存意图投影、最近已提交逻辑矩形、校准后的实际矩形、原始 Offset／Extent 和 EffectiveOffset／EffectiveExtent、是否正在交互、位置差值、有限恢复计数、上次恢复失败及尚未完成的重试。

注意：保存相关字段来自已经加载的配置／最近布局投影快照，并非重新读取磁盘原始存档。没有诊断提供者的窗口仍输出几何证据，不臆造保存字段。每次最多详细输出 64 个现有窗口，超出数量或单个提供者错误会明确标为部分报告。逐窗分节，避免整个位置数组先被单节容量截断。

诊断本身不修复、不保存、不重新加载配置、不创建窗口、不启用业务。读取 Native 失败时保留 unknown／error，不使用缓存回退来证明缓存与 Native 一致。

## 3. 性能影响

不新增永久 Tick、OnUpdate 或后台循环。复用原先每个启动／生命周期稳定序列最多 8 次的 one-shot 检查，原间隔累计约 15.4 秒；生命周期新事件按原策略重新开始稳定序列。

每个同度量检查按现有窗口／显式注册按钮数量线性核对，隐藏或交互中窗口跳过恢复。实际位置没有变化时不重放布局，不触发 Feature 刷新、装备扫描、业务缓存更新或位置保存。此处增加的是启动和生命周期期间的有限 Native 几何读取，不是每帧读取。

内存只增加少量计数以及发生恢复窗口的最新证据和未完成请求，没有无界历史队列。完整坐标快照仅用户打印诊断时临时构建。未做 RU 客户端 CPU、帧耗或内存实测，不给出未经测量的 FPS 改善数字。

## 4. 兼容风险及覆盖方法

退出游戏并备份插件与存档，把补丁 ZIP 中的 `replicatedsuite/` 合并覆盖到 Addon 下同名目录。它是在当前对话前两轮补丁之上的增量包，不是完整插件，不要先删除旧插件目录，不要清空配置。首次覆盖后完整启动客户端，再验证热重载。

BuildTag 仍可能显示 `.18.332`，这是正常的；本次通过诊断中的 `ui-position-reload-1` 识别新逻辑。不会移动窗口到默认出生点，不重新导入 Buff，不改功能启停或业务数据。

本补丁能保留原有保存意图并避免这两类错误恢复路径；已经在历史错误位置再次保存的坐标，不会自动猜回更早的布局。只读恢复不会擅自覆盖这些记录。

剩余验证边界：没有真实 Lua 5.1 编译器，也没有 RU 客户端；Native API 实际返回单位、实际事件投递及原生晚于有限稳定观察窗口才发生的重置，需要实机确认。没有使用永久轮询掩盖这一边界。窗口原生位置持续被外部改写、或其读数不可用时，诊断会保留未知／失败，不能算成恢复成功。

先保留当前窗口摆放截图，挑选跑商／债券／活动等普通悬浮窗，同时保留一个展开窗、一个最小化窗及功能方案、换装、R 按钮。连续热重载 5 次，再完整退出进入游戏 3 次，比较最终位置是否累积变化。验证期间不要先清配置或批量重置位置，否则会破坏原问题证据。
